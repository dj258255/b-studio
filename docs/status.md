# 구현 상태와 일정

README에 있던 "일정과 작업 방식"과 "구현 상태" 절을 옮긴 문서입니다. README는 핵심 설계와 측정 결과만 남기고 영역별 상태와 만든 순서는 여기서 관리합니다.

## 지원 범위

b-studio가 **지원한다고 말하는 범위**는 좁습니다: 한 세션에 요청 하나씩, 로컬 CLI 백엔드(claude-code), 로컬 Docker 샌드박스. 도그푸딩에서 매일 쓰며 고친 경로가 이것이고, 변경을 내보낼 때마다 실제로 돌려 보는 것도 이 경로입니다.

그 밖의 기능은 **실험**입니다. 코드는 그대로 있고 테스트도 돌지만, 기본 화면과 에이전트 도구에서는 숨깁니다. `B_STUDIO_EXPERIMENTAL=1`로 스튜디오를 띄우면 보입니다([설정](configuration.md#실험-기능-b_studio_experimental), ADR-166). 숨기는 것일 뿐 막지 않습니다. API와 페이지 주소, 벤치와 E2E는 그대로입니다.

"마지막 실제 확인"은 테스트가 아니라 **실제 환경에서 돌려 본 마지막 날**입니다. 기록이 없으면 없다고 적었습니다.

### 지원

| 기능 | 마지막 실제 확인 | 무엇으로 |
|---|---|---|

| 로컬 Docker 샌드박스: 기동, 재시작, 파일 반영, `.git` 보호, 연결 상태 | 2026-11-12 | 기동·`.git` 보호·격리를 벗어나는 컨테이너 거절과, 세션 중 compose에 마운트를 더한 뒤 다시 켤 때 override를 다시 써 새 자리의 `.git`을 가리는 것은 만들기 반복을 Rust로 옮긴 뒤 실제 Docker로 봤다(모델 없이, [기록](experiments/2026-11-12-a4c1-up-loop.md), [앞 기록](experiments/2026-11-11-a4b-verify-containers.md)). 파일 반영 확인, 변경 알림, 포트 충돌 뒤 다시 뽑기(충돌 한 번은 꾸밈)는 같은 날 Rust로 옮긴 뒤 실제 Docker로 봤다([기록](experiments/2026-11-12-a4c2-sync-relay-port.md)). 준비 확인, 틀린 준비 경로의 실패, 사라진 edge 복구, 서비스 안에 남은 프로세스를 찾아 다시 띄우기, 일시 오류 뒤 다시 만들기도 같은 날 Rust로 옮긴 뒤 실제 Docker로 봤다([기록](experiments/2026-11-12-a4c3a-readiness.md)). 의존성 스냅샷의 저장·채우기·정리, 공유 볼륨, 사용량 읽기도 같은 날 Rust로 옮긴 뒤 실제 Docker로 봤다([기록](experiments/2026-11-12-a4c3b-snapshots.md)). `exec`, 사내 API 호출, 컨테이너 네트워크 안의 부하 러너와 그 중단, 지우기(`destroy`) 뒤 남는 것이 없는 것도 같은 날 Rust로 옮긴 뒤 실제 Docker로 봤다(스튜디오를 거치지 않고, [기록](experiments/2026-11-12-a4c3c-lifecycle.md)). 연결 상태와 컨테이너를 내려 복구하는 것은 2026-10-10 같은 세션 |
| 게이트의 확인: 재시작·준비, API 계약, 화면 확인(자동 포함), 테스트, 부하 확인, 리뷰 | 2026-11-14 | 재시작·준비와 API 계약은 2026-11-14 실제 세션에서 통과와 실패 양쪽([기록](experiments/2026-11-14-a5a-verify.md)). 테스트와 동시 요청 확인도 2026-11-14 실제 세션에서 통과와 실패 양쪽([기록](experiments/2026-11-14-a5b2-declared-checks.md)). 화면 확인(HTTP·브라우저 모드, api 값)도 2026-11-14 실제 세션에서 통과와 실패 양쪽([기록](experiments/2026-11-14-a5c1-check-page.md)). 자동 화면 확인(브라우저 모드, import로 찾은 동적 경로)도 2026-11-14 실제 세션에서 통과와 실패 양쪽([기록](experiments/2026-11-14-a5c2-auto-pages.md)). 화면 확인 브라우저의 출처 제한(리다이렉트·서비스 워커까지 막는 프록시)도 2026-11-14 실제 세션에서 통과와 막힘 양쪽([트러블슈팅 200](troubleshooting.md#200-화면-확인-브라우저의-출처-제한을-허용-출처의-리다이렉트와-서비스-워커로-넘을-수-있었음--브라우저를-로컬-전달-프록시-뒤에서-띄우고-프록시가-접속-주소를-검사한다)). HTTP 모드 자동 확인은 Next.js 16에서 정상 화면을 오류 화면으로 판정하던 것을 고친 뒤 2026-11-14 실제 세션에서 통과와 스트리밍 도중 서버 오류로 막힘 양쪽([트러블슈팅 199](troubleshooting.md#199-http-모드-자동-화면-확인이-nextjs-16의-정상-화면을-오류-화면으로-판정했음--화면-글자에서-표지를-찾고-스트리밍-도중의-서버-오류는-digest-신호로-잡는다)). 부하 확인·리뷰는 2026-10-10 같은 세션 |
| 통과한 확인의 근거 · QA 탭의 게이트 확인 | 2026-10-10 | 같은 세션. 웹 화면에서 잰 날짜이고 웹 화면은 #896·#917에서 지워졌다(ADR-186). 같은 기능의 desk 화면(실행 화면의 QA 탭)은 이 날짜로 확인한 것이 아니다 |
| 탐색형 QA | 2026-10-10 | 웹 화면의 QA 탭을 3회(지워짐, #896). desk 실행 화면의 QA 탭에서는 확인하지 않았다 |
| 요구사항 추적(명세·추출·현황) | 2026-10-10 | 같은 세션(조회 시간 측정) |
| 테스트 탭 | 2026-10-10 | 같은 세션(게이트가 모은 결과 표시). 웹 화면 기준(지워짐, #896). 지금은 desk 요구사항 화면(`Ctrl-b e`)의 테스트 탭이고 desk에서는 확인하지 않았다 |
| 체크포인트로 되돌리기 · 보관본 되살리기 | 2026-10-10 | 같은 세션 |
| 폴더 열기(기존 프로젝트를 그대로 열기) | 2026-10-10 | 같은 세션이 폴더 열기로 만든 프로젝트다. 새 폴더를 여는 것은 그날 돌리지 않았다 |
| 저장소 탭: 이슈·PR 목록과 상세, 올리기 전 점검 | 2026-10-10 | 웹 화면이 열리는 것까지(지워짐, #896). desk 실행 화면의 저장소 탭에서는 확인하지 않았다. PR 만들기·AI 리뷰를 마지막으로 실제로 돌린 날은 기록하지 못했다(10월 초 도그푸딩) |
| 토큰 탭 · 프로젝트 토큰 보고서 | 2026-10-10 | 같은 세션(실행 시간·토큰 측정, E14). 웹 화면 기준(지워짐, #896). 지금은 desk 기록 화면(`Ctrl-b h`)의 토큰 탭이고 desk에서 그 보고서를 열어 본 기록은 이 표에 없다 |

2026-10-10 행의 "탭"·"화면"은 지워진 웹 화면이고, 위 날짜는 그 화면에서 실제로 돌려 본 날 그대로 뒀습니다. 같은 기능을 지금은 desk에서 쓰는데 desk에서 확인했다는 기록이 없는 행은 desk 경로를 확인하지 않은 것입니다. 날짜는 desk 경로를 실제로 돌려 본 뒤에 바꿉니다.

| 세션 터미널을 이 컴퓨터의 CLI로 열기(기본값. 컨테이너는 `B_STUDIO_TERMINAL=container`): 사용자의 로그인 셸에서 띄우고 훅은 실행 인자로 붙인다 | 2026-10-30 | 2026-10-14에는 진짜 CLI와 가짜 모델로 요청 → 게이트 → 체크포인트, 읽기만 거절, 다시 띄운 CLI의 훅까지 봤다. **실제 Claude Code(2.1.310·2.1.314, 구독 로그인)로는 2026-10-27·30에 desk에서 돌렸다**([1차](experiments/2026-10-27-real-claude-desk.md), [2차](experiments/2026-10-30-real-claude-desk-2.md)): 훅이 지금 줄·서브에이전트 행·문맥 %를 채우고, 게이트 통과와 체크포인트 1개, 끝 알림, 라우팅 기록까지 봤다. 새 작업 복사본마다 폴더 신뢰 창에서 멈추는 것(고침, #966), 선언한 검사가 실패했는데 "검증 통과"로 보이던 것(고침, #989)을 이 실측에서 찾았다. 신뢰 창에는 범수 님 허락을 받아 실측 폴더에서만 답했다. **보지 못한 것**: 권한 대기 문구(사용자 설정이 auto mode), 할 일 막대와 남은 시간 추정, 쓰기 범위 밖 쓰기 거절(범위 밖 경로가 없었음), async 관찰 훅 하나하나의 비동기 실행. 프로젝트는 busybox 하나짜리 작은 저장소이고 한 번씩 본 값이다. 격리가 없고, 관문 파일 변조와 훅 없는 CLI는 감지해 그 실행을 실패로 닫지만 작정한 우회는 막지 못한다. 작업 폴더 `.git`은 직접 커밋을 풀어 검증하고 브랜치 전환을 되돌리며 올리기 전에 브랜치·원격을 확인한다. 개인 PC 모드의 터미널 통로는 `studio launch`가 심은 실행 토큰이 있어야 쓴다(ADR-173, 트러블슈팅 145~148) |

### 2026-10-22에 넣은 기능의 실제 확인 범위

2026-10-22에 넣은 아래 기능은 처음에는 테스트와 가짜 모델로만 확인했습니다. 그 뒤 실제 모델로 본 것과 아직 보지 못한 것을 나눠 적습니다. 세션 터미널에 붙은 것(터미널로 보내기, 에이전트별 토큰)은 터미널과 함께 실험 기능 뒤에 있고, 나머지는 숨기지 않았습니다.

| 기능 | 확인한 범위 | 아직 보지 못한 것 |
|---|---|---|
| desk의 새 요청: 내가 쓴 규칙으로 AI를 골라 세션을 만들고 첫 요청을 보냄, 이번만 다른 AI로 보내기(ADR-179) | 실제 Claude Code로 규칙대로 보내 세션 터미널이 열리고 게이트·체크포인트·라우팅 기록까지 봤다(2026-10-27·30, [1차](experiments/2026-10-27-real-claude-desk.md), [2차](experiments/2026-10-30-real-claude-desk-2.md)). 같은 실측에서 라우팅이 고른 모델이 CLI에 가지 않던 것을 찾아 고쳤다(#988). 규칙표로 Claude Code와 Codex에 요청 하나씩 나눠 보낸 것은 실제 Docker와 로그인한 두 CLI로 확인했다(2026-10-28, [E1-b 덧붙임](experiments/2026-10-28-codex-e1b.md), 컨테이너 방식이 아니라 러너 경로) | desk에서 Codex로 보낸 요청이 게이트까지 가는 것(Codex 터미널은 폴더 신뢰 창까지, [기록](experiments/2026-10-28-codex-terminal.md)), \"이번만 다른 AI로 보내기\"를 실제 모델로 쓴 기록 |
| AI별 결과 표와 미리보기 아래 같은 종류의 기록 | 실제 Claude Code 세션의 기록이 모델별로 쌓이는 것(2026-10-30, 통과 1·실패 2·모델 모름 1), E1-b의 두 AI 각 1회 통과가 표에 쌓이는 것을 봤다 | 표가 고르는 데 쓸 만큼 쌓인 뒤의 모습. 표본은 한두 건씩이다 |
| 다시 검증(지금 체크포인트를 같은 게이트로 처음부터, ADR-181) | 가짜 샌드박스와 진짜 git·게이트로 테스트만 했다 | 실제 Docker 프로젝트로 돌린 것 |
| 확인 필요(에이전트가 요청과 건넨 확인의 어긋남을 `report_mismatch`로 알림, ADR-182) | 실제 Claude Code(Sonnet)로 E15 T2를 다시 쟀다(2026-10-27, 9회, [기록](experiments/2026-10-27-e15-t2-remeasure.md)). 알림 없이 완료로 닫힌 틀린 결과가 9/9에서 0/9가 됐다 | 같은 기록의 한계(결과 자체는 고치지 않고 알리기만 함, 과제 3개). 다른 모델·과제 |
| 요구사항 Ready 배지(고칠 것이 남은 수) | 테스트만 했다 | desk에서 본 것 |
| 에이전트별 토큰과 할 수 있는 범위(메인 터미널 CLI와 서브에이전트, `studio desk`) | 진짜 Claude Code 2.1.308·Codex 0.160.1을 가짜 모델에 붙여 받은 텔레메트리를 넣어 내역의 합이 CLI 합계와 같은 것을 봤다. 실제 Claude Code 세션에서 서브에이전트가 `agents`에 행으로 실리고 그 토큰이 붙는 것도 봤다(2026-10-30 2차) | 서브에이전트 토큰 내역이 CLI 합계와 맞는지를 실제 모델로 대조한 것 |

### 이 구분이 뜻하는 것

- 마찰을 고칠 때 실험 경로까지 같이 고치지 않습니다. 대신 PR에 "이 경로는 확인하지 않았다"를 적습니다([작업 규칙](../AGENTS.md)).
- 실험 기능을 지원으로 올리려면 실제 환경에서 돌린 기록이 먼저 있어야 합니다.
- 한 분기 뒤(2027-01)에 쓰임을 보고, 그때도 쓰지 않는 것은 지울지 정합니다. 그 전에는 지우지 않습니다. 실험 기록(E1~E18)을 다시 돌릴 수단이기 때문입니다.
