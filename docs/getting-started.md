# 시작하기

이 문서는 로컬 Docker에서 주문 예제를 실행하고 첫 에이전트 요청을 보내는 데까지 안내합니다.

## 1. 요구 사항

| 항목 | 요구 사항 |
|---|---|
| Node.js | 22 이상 |
| pnpm | 10.29.3 (`packageManager` 기준) |
| 컨테이너 런타임 | Docker Desktop 또는 Colima |
| Git | 체크포인트와 원격 저장소 연동에 필요 |
| 모델 인증 | Anthropic API 키 또는 로그인된 Claude Code CLI |

처음 실행할 때 Docker가 Node, Java, PostgreSQL 이미지와 의존성을 내려받으므로 시간이 걸릴 수 있습니다.

## 2. 저장소 설치

```bash
git clone https://github.com/dj258255/b-studio.git
cd b-studio
corepack enable
pnpm install
```

기본 검사를 먼저 실행하면 로컬 환경 문제를 일찍 찾을 수 있습니다.

```bash
pnpm test
pnpm typecheck
```

## 3. 주문 예제 실행

```bash
pnpm studio up examples/orders
```

b-studio는 명세와 compose 구성을 검증하고, 샌드박스를 만든 뒤 각 서비스의 준비 상태를 확인합니다. 준비가 끝나면 미리보기와 OpenAPI 주소를 출력합니다.

종료할 때는 `Ctrl+C`를 한 번 누르세요. 디버깅을 위해 컨테이너를 남기려면 `--keep`을 붙입니다.

```bash
pnpm studio up examples/orders --keep
```

## 4. 웹 스튜디오 실행

```bash
# 모델 없이 세션 흐름 확인
pnpm studio:demo

# 개인 PC의 Claude Code 로그인 사용
claude --version
pnpm studio:local
```

브라우저에서 `http://127.0.0.1:3000`을 열면 **바로 개발 화면(대화 + 미리보기)** 이 열립니다([ADR-066](decisions.md#adr-066-첫-화면은-마지막-프로젝트의-개발-화면이다)). `claude-code` 모드는 로그인된 개인 PC에서만 사용하세요. 여러 사용자가 접속하는 서버에서는 API 모드와 웹 인증을 구성해야 합니다.

- 첫 화면은 마지막으로 쓴 프로젝트의 세션을 고릅니다. 켜진 세션이 있으면 그것을, 없으면 가장 최근 세션을 같은 작업 복사본으로 이어서 열고, 세션이 없으면 새로 만듭니다. 샌드박스는 그 자리에서 켜기 시작하므로 켜지는 동안 요청을 적으면 됩니다(처음이면 1분 안팎). 여러 명 비교 참가자·나눠서 병렬 레인은 고르지 않습니다.
- `http://127.0.0.1:3000/?project=<id>`면 그 프로젝트의 개발 화면을 엽니다.
- **내 프로젝트 폴더 열기**: 개발 화면 머리의 **프로젝트 이름**을 누르고 **폴더 열기…**에 경로(예: `~/Desktop/my-app`)를 넣은 뒤 **살펴보기**를 누릅니다([ADR-067](decisions.md#adr-067-아무-폴더나-프로젝트로-연다-스택을-알아내-실행-설정을-만들고-git-추적에서-뺀다)). 개인 PC 모드(인증 없음)에서만 보입니다.
  - `studio.yaml`이 없으면 Next.js·Vite·Spring Boot·FastAPI를 찾아 만들 파일을 먼저 보여 줍니다(`studio.yaml`·`compose.b-studio.yaml`·`Dockerfile.b-studio`).
  - **파일을 만들고 열기**를 누르면 파일을 쓰고 git 추적에서 뺀 뒤(`.git/info/exclude`, 저장소 기록은 바뀌지 않음) 그 프로젝트의 개발 화면을 엽니다.
  - 등록한 폴더는 `~/.config/b-studio/projects.json`에 남습니다.
- 다른 프로젝트로 바꾸거나, 이 프로젝트로 새 대화를 시작하거나, 최근 세션·토큰 보고서를 보려면 개발 화면 머리의 **프로젝트 이름**을 누릅니다([ADR-070](decisions.md#adr-070-새로-시작-화면을-없애고-개발-화면-머리에-프로젝트-메뉴를-둔다)). 화면을 옮기지 않고 팝오버로 뜹니다. 켜진 개발 세션이 있으면 첫 화면은 기다림 없이 바로 그 세션으로 갑니다.
- 대화는 그냥 치면 됩니다. 이 세션의 에이전트가 처리하고, 일이 서비스별로 뚜렷이 나뉘거나 여러 안을 비교할 만하면 먼저 **제안 카드**를 띄웁니다([ADR-068](decisions.md#adr-068-대화는-한-명이-처리하고-나눌-만하면-에이전트가-제안한다)). **나눠서 병렬로 하기**나 **여러 안 비교하기**를 누르면 화면을 옮기지 않고 **대화 안에 진행 카드**가 생깁니다([ADR-069](decisions.md#adr-069-넘긴-작업도-대화-안에서-보고-방식은-어디서도-고르게-하지-않는다)). 카드에서 계획을 승인·거절하고, 레인 진행을 보고, 비교 결과 중 하나를 고릅니다. **한 명으로 계속**을 누르면 이 대화에서 이어 갑니다. 방식(한 명·여러 명 비교·나눠서 병렬)을 사람이 고르는 곳은 없습니다.
- 머리의 **작업** 버튼은 보낸 요청 목록을 개발 화면 오른쪽 패널로 엽니다.

### 한 번에 켜기 (`launch`)

위 두 명령 대신 한 명령으로 켜고 끌 수 있습니다. Docker가 꺼져 있으면 colima를 켜고, 준비되면 브라우저를 엽니다. 이미 떠 있으면 새로 띄우지 않고 브라우저만 엽니다.

```bash
pnpm studio launch              # 이 PC의 Claude Code로 (기본)
pnpm studio launch --mode demo  # 모델 없이 화면·흐름만
pnpm studio launch --mode codex --port 3100
pnpm studio stop
```

- `--mode`: `local`(기본, `B_STUDIO_MODE=claude-code`) · `demo` · `commandcode` · `codex`
- `--port`: 기본 3000 · `--no-open`: 브라우저를 열지 않고 주소만 출력
- `--json`: 브라우저를 열지 않고, 준비되면 stdout에 한 줄 JSON만 출력(진행 안내는 stderr). 데스크톱 앱이 이 출력으로 창을 엽니다
- 로그: `~/.cache/b-studio/launch/studio.log`, PID: `~/.cache/b-studio/launch/studio.pid`

준비 로그는 위 파일에 남고, 준비되지 않으면 끝 20줄을 보여 주고 종료 코드 1로 끝납니다. `stop`은 PID 파일의 프로세스 그룹에 SIGTERM을 보내고 파일을 지웁니다(로그는 남습니다).

프로그램이 열 주소와 PID를 알아야 하면 `--json`을 씁니다.

```bash
pnpm studio launch --json
# {"url":"http://127.0.0.1:3000","port":3000,"mode":"claude-code","pid":12345,"started":true}
pnpm studio stop --json
# {"stopped":true}
```

`started`는 `launch`가 이번에 새로 띄웠으면 `true`, 이미 떠 있어 브라우저만 열었으면 `false`입니다. 준비에 실패하면 JSON을 쓰지 않고 종료 코드 1로 끝납니다.

문제가 생기면:

- **포트를 이미 쓰는 중**: `launch`가 "다른 프로그램이 응답합니다"라고 하면 `--port 3100`처럼 다른 포트를 씁니다.
- **Docker가 꺼져 있음**: colima가 설치돼 있으면 `launch`가 자동으로 켭니다. 없으면 Docker Desktop을 켜세요.

### 데스크톱 앱 (macOS)

터미널 없이 더블클릭으로 켜려면 얇은 Electron 껍데기를 설치합니다. 화면은 웹 스튜디오 그대로이고, 앱은 **서버 켜기·창·도구 막대(주소창)·메뉴**만 합니다([ADR-062](decisions.md#adr-062-데스크톱은-얇은-electron-껍데기로-두고-웹-스튜디오를-본체로-남긴다)).

```bash
pnpm desktop:install
```

1. `~/Applications/b-studio.app`이 만들어집니다(서명하지 않습니다).
2. **처음 한 번은 Finder에서 앱을 우클릭 → 열기**로 열어야 합니다. 그냥 더블클릭하면 "확인되지 않은 개발자" 경고가 뜹니다(한 번 열면 다음부터는 그냥 열립니다).
3. 앱은 저장소에서 스튜디오 서버를 스스로 켭니다(이미 떠 있으면 그 서버를 그대로 씁니다). 처음에는 Docker·Colima를 켜느라 몇 분 걸릴 수 있고, 그동안 창에 진행 안내가 보입니다.
4. 창 위 도구 막대: 뒤로·앞으로·새로고침·주소창·"브라우저에서 열기". 주소창에는 `127.0.0.1:3000`, `3100`(미리보기 포트), `/sessions/…`(스튜디오 안 경로)를 넣을 수 있습니다. **이 PC 주소만** 앱 안에서 열리고, PR 링크 같은 외부 주소는 기본 브라우저로 넘어갑니다.
5. 창을 닫으면 앱이 끝나고, **앱이 켠 서버만** 함께 중지됩니다. 사람이 터미널에서 켠 서버는 그대로 둡니다. 앱을 열어 둔 채 서버만 끄려면 메뉴의 "스튜디오 중지"를 씁니다.

**문제가 생기면**

- "설정 파일이 없습니다" 또는 "서버를 켜지 못했습니다" 화면이 뜨면 `pnpm desktop:install`을 다시 실행하세요. 설정 파일(`~/.config/b-studio/desktop.json`)에 저장소 루트·node·pnpm 경로가 들어 있는데, 저장소를 옮겼거나 node 버전을 바꿨으면 이 값이 낡습니다.
- 기동 로그는 `~/.cache/b-studio/launch`에 남습니다. 실패 화면의 "로그 폴더 열기" 버튼이나 메뉴의 같은 항목으로 열 수 있습니다.
- 지우려면 `~/Applications/b-studio.app`을 지우고, 원하면 설정 파일도 지웁니다(다음에 다시 설치하면 새로 씁니다).
- 개발 중에는 서버를 따로 띄워 두고 `pnpm desktop:dev`로 앱만 실행해 볼 수 있습니다.

### 진행 중 지시

에이전트가 작업하는 동안에도 대화 입력창은 열려 있고, 보내기 버튼이 "진행 중 지시"로 바뀝니다. 실행 중에 보낸 말은 **다음 모델 호출 직전**에 대화에 들어가고, 지금 하던 도구 호출(테스트 실행처럼 몇 분 걸리는 것)을 중간에 끊지는 않습니다. 그래서 긴 도구 호출이 끝난 뒤에 반영될 수 있습니다. 대화에는 "지시(대기)" → "지시(반영됨)" 상태로 남고, 실행이 끝날 때까지 반영되지 못한 지시는 "지시(적용되지 못함)"으로 표시됩니다.

`api`·`claude-code`·`codex` 모드가 지원하고, 데모(스크립트) 모드는 지원하지 않습니다. 작업 분해의 레인·플릿·벤치에는 켜지 않습니다(사람이 보는 단일 세션만).

## 5. 첫 에이전트 요청

```bash
# Anthropic API
export ANTHROPIC_API_KEY="..."
pnpm studio agent examples/orders "주문 목록에 상태 필터를 추가해 줘"

# Claude Code 로그인
pnpm studio agent examples/orders \
  "주문 목록에 상태 필터를 추가해 줘" \
  --backend claude-code
```

| 옵션 | 의미 |
|---|---|
| `--backend api\|claude-code` | 모델 실행 방식 선택 |
| `--model <id>` | 사용할 모델 지정 |
| `--effort low\|medium\|high\|xhigh\|max` | 추론 노력 수준 지정 |
| `--logs` | 서비스 로그를 함께 출력 |
| `--allow-breaking` | 요청이 명시한 API 호환성 파괴 허용 |
| `--keep` | 종료 또는 실패 뒤에도 샌드박스 유지 |

### 요청과 질문을 한 입력에서

대화 입력창은 **하나**입니다. 만들기/질문을 미리 고르지 않고, 에이전트가 요청을 보고 답만 할지 바꿀지 정합니다([ADR-042 보강](decisions.md#adr-042-질문-모드-같은-대화와-도구-목록을-쓰고-바꾸는-도구는-실행기에서-막는다)).

- **바꾸는 요청**이면 파일을 고치고, 바꾼 것은 검증 게이트를 통과해야 남습니다.
- **묻는 요청**이면 코드를 읽고 답하거나 계획만 세웁니다. 파일을 바꾸지 않았으므로 게이트가 돌지 않고 체크포인트도 남지 않으며, 결과 줄에 **"답만 했습니다(바꾼 파일 없음)"** 이라고 표시됩니다.
- **"읽기만" 스위치**(기본 꺼짐)를 켜면 파일을 바꾸는 도구를 아예 쓸 수 없습니다(읽기 전용 실행). 꼭 바뀌면 안 되는 상황이나 계획만 받고 싶을 때 쓰세요. 스위치는 세션마다 기억되고, 답 아래의 **"이대로 만들기"** 로 그 계획을 그대로 실행할 수 있습니다.
- **"가볍게 확인" 스위치**(기본 꺼짐, 읽기만이 켜지면 숨김)를 켜면 검증 게이트가 **서비스 재시작·준비 판정·계약 비교만** 하고 테스트·화면 확인·리뷰는 건너뜁니다. 작은 변경을 빠르게 확인할 때 쓰세요. 건너뛴 단계는 배포 조건을 채우지 못하므로 **배포하려면 전체 검증을 다시 받아야 합니다.** 결과 줄에 "가볍게 확인: 테스트·화면 확인·리뷰를 건너뛰었습니다"라고 표시되고, 기록 탭의 체크포인트에는 "가볍게" 배지가 붙습니다. 이 스위치도 세션마다 기억됩니다.
- 실행 중에는 지금처럼 **"진행 중 지시"** 로 보냅니다(다음 모델 호출 직전에 반영됩니다). 그때는 스위치가 뜻이 없어 나란히 보기 칸에서는 감춥니다.
- 나란히 보기(`/split`)의 칸에도 같은 입력과 같은 스위치가 있습니다.

### 되묻기(질문 카드)

요청이 모호해 결과가 크게 달라질 것 같으면, 에이전트가 만들기 전에 **선택지로 한 번 되묻습니다**(`ask_user` 도구). 실행을 붙잡고 답을 기다리지 않고 **질문을 남기고 끝나므로**, 연결이나 시간 제한에 걸리지 않고 스튜디오 서버가 다시 시작돼도 질문이 대화 기록에 남습니다.

- 대화에 질문 카드(질문 문장 + 선택지 버튼, 필요하면 직접 입력칸)가 뜨고, 고른 답이 다음 요청으로 보내집니다. 이어받기를 지원하는 러너(API, Claude Code)는 같은 대화를 그대로 이어 가고, Codex는 최근 요약 맥락으로 이어 갑니다.
- 사람이 없는 실행(작업 분해 레인·플릿·벤치·CLI)에는 이 도구가 들어가지 않아 지금처럼 짐작으로 진행합니다.
- 데모 모드(`pnpm studio:demo`)는 첫 요청에서 질문 카드를 보여 주고, 답을 누르면 준비된 대본을 이어서 실행합니다.

### 나란히 보기

세션 2~4개를 한 화면에 띄워 대화와 상태를 실시간으로 보고, 칸마다 요청을 보낼 수 있습니다.

- 작업 화면(`/work`)에서 줄을 골라 "선택한 것 나란히 보기"를 누르거나, 세션 화면 헤더의 "나란히 보기에 추가"로 지금 세션을 목록에 붙입니다. 주소는 `/split?ids=a,b,c`입니다.
- 2개면 좌우, 3~4개면 2×2로 배치합니다. 좁은 화면(900px 미만)에서는 위아래로 쌓이고, 칸 머리를 눌러 접을 수 있습니다.
- 칸마다 세션 화면과 같은 실시간 이벤트를 받습니다. 도구 호출은 한 줄만 보여 주고 결과 본문은 접습니다. 자세한 내용은 "크게 보기"로 세션 화면에서 봅니다.
- 실행 중인 세션에 보내면 새 요청이 아니라 **진행 중 지시**로 들어가, 다음 모델 호출 직전에 반영됩니다(데모 모드는 지원하지 않습니다).
- 요청 권한은 서버가 판단합니다. 만든 사람이 아니면 403과 함께 "이 세션은 만든 사람만 바꿀 수 있습니다"가 칸에 표시됩니다.

## 6. 작업 분해

웹 스튜디오의 "작업 분해"에서 한 요청을 여러 레인(세션)으로 나눠 동시에 실행합니다. 모델이 작업·쓰기 범위·의존 관계를 제안하고 스튜디오가 검증하면, 사람이 승인한 뒤 레인마다 세션을 띄웁니다. 모든 레인이 게이트를 통과하면 새 세션에서 결과를 합쳐 같은 게이트로 다시 검증합니다.

### 관계 그래프

계획 카드의 "그래프" 보기로 레인·작업·통합과 그 사이의 관계를 한 그림에서 봅니다(기존 "목록" 보기와 전환).

- 노드: 왼쪽부터 레인 한 열씩, 레인 안 작업이 위에서 아래 순서, 통합이 맨 오른쪽 한 칸입니다. 노드마다 상태를 색과 함께 아이콘·글자(● 완료 / ◐ 실행 중 / ○ 대기 / ✕ 실패 / ! 범위 위반)로 보여 줍니다. 레인이 쓰기 범위 밖 파일을 바꿨으면 범위 위반으로 표시합니다.
- 간선: 작업 의존(같은 레인이면 세로, 다른 레인이면 가로 곡선), 작업 → 통합, 게시판 메모(작성 레인 → 읽을 수 있는 레인)입니다. 메모 종류별로 선 모양이 다릅니다(계약 실선, 실패 점선, 사실 가는 선). 조율 topology가 star면 레인끼리 직접 잇지 않고 허브(통합)를 거쳐 그립니다.
- 노드를 누르면(또는 Tab으로 옮겨 Enter) 오른쪽 패널에 작업 요청 앞부분·실행 결과 요약·토큰·시간·쓴 메모가 나옵니다. 메모 선을 누르면 메모 본문이 나옵니다.
- 실행 중에는 계획 카드의 2초 갱신 주기로 그래프도 다시 그립니다. 화면이 좁으면(390px) 그래프 영역을 가로로 밀어 봅니다.

## 7. 토큰 사용 보고서

한 프로젝트의 모든 세션(작업 분해 레인·통합·Fleet 멤버 포함)이 쓴 토큰과 b-studio가 줄인 양을 한 장에 모아, 과제·포트폴리오 README에 그대로 붙일 수 있게 합니다.

- 개발 화면 머리의 프로젝트 메뉴에서 **토큰 보고서**를 누르면 `/projects/<id>/tokens`로 들어갑니다. 화면에는 쓴 양(총 토큰·환산 비용·요청 수·캐시 적중률·모델별 표·요청별 표)과 줄인 양이 **측정**과 **추정**으로 나뉘어 나옵니다.
- "마크다운으로 복사"는 같은 내용을 클립보드에 넣고, "파일로 받기"는 `.md` 파일로 내려받습니다. 서버 주소 `GET /api/projects/<id>/token-report?format=markdown`으로도 받을 수 있습니다. `?from=2026-09-01&to=2026-09-30`처럼 기간을 줄 수 있고, `download=1`이면 파일로 내려줍니다.
- 보기는 로그인한 사람이면 누구나 할 수 있습니다. 세션 기록을 바꾸지 않습니다.

**한계**

- **환산 비용은 추정**입니다. 단가(`B_STUDIO_PRICE_*`, `B_STUDIO_TOKEN_PRICES_JSON`)를 넣었을 때 공식 단가로 환산한 값이라 구독 요금과 다릅니다. 단가를 못 찾은 실행이 하나라도 있으면 합계 비용을 쓰지 않고 그 사실을 적습니다(일부만 계산한 합계는 실제보다 싸 보이기 때문입니다).
- **줄인 토큰은 추정**입니다. 잘라낸 글자를 4로 나눠 토큰으로 본 근사이고, 자르지 않았다면 그 글자가 남은 모델 호출마다 다시 실려 갔을 양을 셉니다. 잘라낸 글자·비운 글자·반복 대체 같은 측정값과 화면에서 따로 표시합니다.
- 모델별 내역을 남기지 않는 러너(구독 CLI 등)의 토큰은 "(모름)"으로 묶습니다. 러너가 모델 이름을 남기지 않아 어느 모델이 썼는지 알 수 없기 때문입니다.
- 시각을 기록에 남기지 않은 실행은 기간을 줄 때 빠지고, 몇 개가 빠졌는지 "알아둘 점"에 적습니다.
- 레인·통합·Fleet 표시는 내 계획·플릿 기록에서 찾은 세션에만 붙습니다(남의 기록은 일반으로 보입니다).
