# 핵심 결정 요약

b-studio를 처음 보는 분을 위해, ADR 199개 중 이 도구의 생각을 이루는 결정 열두 묶음을 골라 요약했습니다.
- 각 묶음은 **무엇이 문제였나 → 무엇을 버리고 무엇을 골랐나 → 그 결과**를 적고, 원문 ADR로 이어집니다.
- 숫자는 모두 원문 ADR과 실험 보고서에 있는 값입니다. 재지 않은 것은 재지 않았다고 적었습니다.

## 한 줄로

에이전트가 "끝났다"고 말해도 믿지 않습니다. 플랫폼이 서비스를 다시 띄우고 준비 상태·API 계약·실제 브라우저 화면·테스트로 직접 확인한 변경만 Git 커밋과 DB 덤프로 남깁니다. 아래 결정은 모두 이 한 줄을 지키려고, 또는 그 판정의 틈을 막으려고 내린 것입니다.

## 1. 완료는 플랫폼이 판정한다

- **문제**: 에이전트의 "끝났다"는 말만으로는 서버가 뜨는지, API 계약을 깨지 않았는지 알 수 없습니다. 또 `workflow.required`에 `test`·`review`를 적어도, 루프는 단계 이름을 알리기만 하고 실행하지 않았습니다. 선언만 있으면 통과처럼 보였습니다.
- **버린 것**
  - SDK Tool Runner: 턴 뒤 검증과 재개를 훅으로 끼워야 합니다.
  - Managed Agents: 코드가 b-studio의 샌드박스에서 돌아야 한다는 요구와 맞지 않습니다.
  - 실행 수단이 없는 필수 단계를 건너뛰기: 그러면 "0건 실패"가 "검사 안 함"과 같은 모양이 됩니다.
- **고른 것**: 루프를 직접 썼습니다.
  - 에이전트가 턴을 끝내면 게이트가 바뀐 서비스를 재시작하고 `run → contract_check → browser_check·test → review`를 직접 실행합니다.
  - 실행할 대상이 없는 필수 단계는 설정을 불러올 때 거부합니다.
  - 통과한 단계는 `Workflow-Passed:` 커밋 트레일러로 남고, 배포 조건과 대조됩니다.
- **결과와 대가**: 이 원칙이 README의 첫 번째 핵심 설계입니다. 대가로, 요청마다 선언한 테스트를 다시 돌리느라 게이트가 느려집니다.
- 원문: [ADR-010](decisions.md#adr-010-에이전트-루프-직접-작성한-루프와-스튜디오-검증-게이트) · [ADR-049](decisions.md#adr-049-워크플로-강제-필수-단계는-게이트가-직접-실행해-통과-기록을-남겨야-완료다)

## 2. 게이트를 비켜 가는 길을 막는다

게이트가 있어도 그것을 거치지 않는 길이 있으면 소용없습니다. 실제 사용에서 찾은 틈 셋입니다.

- **게이트를 거치지 않은 커밋**
  - 문제: 보관본을 되살린 뒤 파일을 한 번도 쓰지 않은 요청이 게이트 없이 끝났습니다. 그런데도 파일 19개(+680/-25줄)가 `Workflow-Passed: none`인 체크포인트가 됐습니다.
  - 고친 것: 체크포인트를 만드는 가장 낮은 공유 지점에서, 코드 변경인데 통과 기록이 없으면 거부합니다. 커밋은 게이트가 검증한 내용의 지문과 같을 때만 됩니다.
  - [ADR-132](decisions.md#adr-132-되살린-변경을-쓰지-않은-요청도-검증-게이트를-거치게-하고-체크포인트-저장-지점에-마지막-방어선을-둔다)
- **에이전트가 계산한 "보인다"**
  - 문제: 안쪽 스크롤 영역에 잘린 버튼이 "글자가 DOM에 있다"는 확인을 통과했습니다. 에이전트는 CSS 값으로 "합계 608px < 720px"라고 계산해 보고했습니다.
  - 고친 것: `expectInViewport`를 게이트가 직접 잽니다. 투명한 글자, 2px 미만 상자, 잘린 요소는 숨겨진 것으로 봅니다. 모델은 호출하지 않습니다.
  - 그 뒤 측정을 페이지와 격리된 실행 환경으로 옮겨, 페이지가 측정값을 바꿔치지 못하게 했습니다(ADR-199).
  - [ADR-161](decisions.md#adr-161-화면에-글자가-보이는지는-에이전트의-계산이-아니라-게이트가-dom에서-잰다)
- **에이전트가 고칠 수 있는 판정 근거**
  - 사람 확인 기록, 마지막 체크포인트, 테스트 결과처럼 판정이 믿는 파일을 에이전트의 쓰기 도구나 컨테이너가 고칠 수 있었습니다.
  - 고친 것: 실행 시작 때 고정한 값과 견줘 바뀌면 실패시킵니다. 컨테이너에서는 `.git` 상태 폴더를 읽기 전용으로 가립니다.
  - [ADR-157](decisions.md#adr-157-요구사항-문서의-검증-기록은-에이전트-실행이-바꿀-수-없다-게이트가-실행-전-문서와-견주고-문서를-지키는-안전망은-되돌려-적는다) · [ADR-158](decisions.md#adr-158-서비스-컨테이너에서-작업-복사본의-git은-쓸-수-없고-b-studio-상태-폴더는-보이지-않는다-컨테이너-마운트에서-git을-가린다)

## 3. 앱은 서버의 실제 샌드박스에서 돌린다

- **문제**: AI가 만든 코드를 바로 보여 줘야 합니다. 브라우저 안에서 번들링하면 빠릅니다(토스 TOI는 첫 화면을 47초에서 1.3초로 줄였습니다). 그러나 b-studio는 Next.js 같은 서버 프레임워크와 백엔드까지 돌려야 합니다.
- **버린 것**
  - 브라우저 번들러: SSR·Server Action이 안 됩니다.
  - WebContainers: Next 16 기본 설정으로 `next dev`가 실패합니다.
  - Nodebox
- **고른 것**: 서버 샌드박스에서 실제 Linux와 실제 개발 서버를 돌립니다.
  - 콜드 스타트는 공유 캐시, lockfile 해시별 스냅샷, 제공자 추상화로 줄입니다.
- **실제 환경에서만 드러난 것**: macOS colima에서 게이트가 컴파일 에러가 있는 코드를 "준비 완료"로 통과시켰습니다.
  - 원인: 파일 공유 캐시 때문에 VM이 방금 쓴 파일을 보지 못한 채 재시작해, 옛 코드가 빌드됐습니다.
  - 그래서 재시작 전에 컨테이너 안에서 이름과 sha256이 호스트와 같은지 확인합니다. 새 폴더는 상위 폴더 목록이 약 19초 늦게 바뀌어서, 상위 폴더까지 모두 봅니다.
- 원문: [ADR-001](decisions.md#adr-001-미리보기-런타임-브라우저-번들러-대신-서버-샌드박스) · [ADR-014](decisions.md#adr-014-재시작-전에-샌드박스가-바뀐-파일을-보는지-확인한다)

## 4. 통과한 변경만 남긴다: Git과 DB를 한 묶음으로

- **문제**: "완료로 인정하지 않는다"와 "적용되지 않았다"는 다릅니다. 게이트가 막아도 바뀐 파일은 남아 있었습니다. 파일만 되돌리면 DB에는 마이그레이션 기록과 새 열이 남아, 코드와 스키마가 어긋난 채 작업이 이어졌습니다.
- **버린 것**
  - 에이전트가 쓴 파일을 기억해 복원하기: 삭제·이름 변경을 직접 구현해야 합니다.
  - Flyway undo 스크립트: 사용자 코드에 강제됩니다.
  - DB 볼륨 복사: Postgres를 멈춰야 합니다.
- **고른 것**
  - 작업 복사본을 Git 저장소로 관리합니다. 통과하면 커밋하고, 실패하면 버린 변경을 patch로 보관한 뒤 되돌립니다.
  - 체크포인트마다 `pg_dump`를 남깁니다. 되돌릴 때는 임시 DB에 넣고 이름을 바꿉니다. 그래서 중간에 실패해도 반쯤 들어간 DB가 남지 않습니다.
- **결과**: 세션 복구 실측에서 DB 복원이 526ms 걸렸고, 강제 종료 전 체크포인트 시점과 `pg_dump` 해시가 같았습니다.
- 그 뒤 고친 것
  - 샌드박스·도커 쪽 실패는 에이전트의 실패로 세지 않고 되돌리지 않습니다(ADR-162).
  - 턴 상한에 걸린 실행은 되돌리기 전에 게이트를 한 번 더 보고, 통과하면 `Workflow-Incomplete: max_turns`를 달아 남깁니다(ADR-131).
- 원문: [ADR-018](decisions.md#adr-018-세션-체크포인트-검증을-통과한-변경만-남긴다) · [ADR-022](decisions.md#adr-022-데이터베이스-브랜치-체크포인트마다-db-상태를-함께-남긴다) · [ADR-131](decisions.md#adr-131-실행-실패로-되돌릴-때-db도-마지막-덤프-시점으로-되돌리고-턴-상한은-설정할-수-있게-하며-걸리면-게이트를-한-번-더-본다)

## 5. 샌드박스의 출입구는 하나, 시크릿은 보이지 않게

- **네트워크**
  - 문제: 실측해 보니 web 컨테이너가 인터넷, npm, 같은 VM에 있는 다른 프로젝트의 Postgres에 모두 연결됐습니다.
  - 고른 것: 모든 서비스를 내부 네트워크에만 둡니다. 외부에 닿는 것은 edge 컨테이너 하나이고, 그 프록시는 허용 목록의 80·443만 통과시킵니다. IP 직접 접속과 사설 주소로 풀리는 이름은 거부합니다.
  - 결과: 직접 `1.1.1.1:443`은 `ENETUNREACH`, 허용한 `registry.npmjs.org:443`은 `200 Connection Established`, 허용하지 않은 곳은 403이었습니다.
  - 대가: HTTP(S)가 아닌 외부 연결은 쓸 수 없습니다.
- **시크릿**
  - 문제: 값이 컨테이너 환경에 있으면 `printenv` 한 번으로 모델 대화와 커밋 본문에 남습니다.
  - 고른 것: `studio.yaml`에는 이름만 적습니다. 값은 서버 환경에서 `docker compose` 프로세스로만 넘기고, 출력에서는 원래 값·URL 인코딩·base64를 가립니다.
  - 원문이 인정한 한계: 문자열 일치라서 다른 인코딩이나 작정한 우회는 막지 못합니다.
- 원문: [ADR-024](decisions.md#adr-024-네트워크-격리-샌드박스의-출입구를-하나로-만든다) · [ADR-025](decisions.md#adr-025-시크릿-주입과-가림-값은-보이지-않게-넣고-새는-경로를-막는다)

## 6. 확인하는 쪽과 실제로 접속하는 쪽을 같게

- **문제**: 화면 확인 브라우저는 허용한 출처만 열어야 합니다. 그런데 실제 Chromium으로 재 보니 두 길이 열려 있었습니다.
  - 허용 출처가 허용 밖으로 리다이렉트하면 그대로 따라가 본문까지 읽혔습니다.
  - 서비스 워커의 요청은 페이지 라우트를 거치지 않았습니다.
  - 원인: 확인하는 계층(페이지 라우트)과 실제로 접속하는 계층(네트워크 스택)이 달랐습니다.
- **고른 것**: 브라우저를 로컬 전달 프록시 뒤에서 띄웁니다.
  - 라우트와 같은 판정 함수로 확인하고, 판정한 주소로만 접속합니다.
  - 막을 때는 403을 주지 않고 연결을 끊습니다. 상태 코드를 보지 않는 확인이 403을 통과로 읽을 수 있기 때문입니다.
  - 프록시를 세우지 못하면 브라우저를 띄우지 않습니다.
- **이 원칙의 일반형**은 [에이전트 작업 규칙](../AGENTS.md#게이트와-판정을-고칠-때)의 첫 질문입니다. "확인하는 쪽과 실제로 동작하는 쪽이 같은 입력을 다르게 읽는가." 경로 검사, 파일 이름 비교, 인증 판단에서 같은 꼴의 틈이 여러 번 나왔습니다.
- 원문: [ADR-198](decisions.md#adr-198-화면-확인-브라우저의-출처-제한은-라우트에-더해-로컬-전달-프록시가-접속-주소를-검사한다)

## 7. 엮인 병렬 작업은 계약을 먼저 게시한다

- **문제**: 인터페이스로 엮인 두 작업(api 응답 ↔ web 화면)을 레인으로 나눠 병렬로 돌렸습니다. 결과는 9회 중 4회만 성공이었습니다.
  - 실패 5건은 모두 레인 경계의 필드 이름·모양 불일치였습니다.
  - 5건 다 레인마다 게이트는 통과한 **거짓 성공**이었습니다.
- **비교**: 같은 과제를 전략마다 9회씩 돌렸습니다.

  | 전략 | 성공 |
  |---|---|
  | S1 공유 없음 | 4/9 |
  | S2 계약 먼저 게시 | 9/9 |
  | S3 게시판 | 8/9 |
  | S4 통합 뒤 수리 | 5/9 |
  | S5 실패 서명 공유 | 8/9 |

  - 사전에 정한 비교는 S2 9/9 대 S1 4/9(p = 0.029)입니다.
  - 결과를 본 뒤 묶은 "계약 공유 17/18 대 비공유 9/18(p = 0.007)"은 사후 탐색이라고 원문에 정정해 두었습니다.
- **고른 것**: 엮인 작업은 계약을 먼저 게시하는 쪽(S2)을 기본으로 둡니다. 조율은 켤 때만 동작합니다.
- 원문: [ADR-059](decisions.md#adr-059-계약으로-엮인-병렬-작업은-계약을-먼저-게시하고s2-조율은-켤-때만-한다) · [E1](experiments/2026-09-29-e1-isolated-parallel-baseline.md) · [E2](experiments/2026-09-29-e2-coordination-strategies.md)
- 작업 분해와 병렬 실행은 지금 실험 기능입니다(10절).

## 8. 토큰은 잰 뒤에 줄인다

- **어디서 새는지 먼저 잼**
  - 같은 과제에서 b-studio는 그냥 Claude Code보다 토큰을 2배 썼습니다.
  - 호출 단위로 쪼개 보니 고정 문맥은 오히려 1/6이었습니다. 추가분의 78%는 도구 결과를 다시 읽는 데 들었습니다.
- **도구 결과 예산**
  - 규칙 기반으로 자릅니다. 명령 출력은 앞이 아니라 뒤쪽을 남깁니다. 실패 요약이 로그 끝에 있기 때문입니다.
  - 같은 결과가 반복되면 대체하고, 턴마다 기록합니다.
  - 결과: 캐시 읽기가 34.4% 줄었고 성공은 9/9로 같았습니다. 다만 원문은 "b-studio 안의 누수를 줄였을 뿐 더 싸게 만들지는 못했다"고 적었습니다.
- **게이트가 하는 확인을 에이전트가 되풀이하지 않게(lean)**
  - 성공은 9/9 그대로였고, 토큰이 41% 줄었습니다.
  - p = 0.164라서 9쌍으로는 경향까지만 말할 수 있습니다.
- **기각한 통념: "계획은 큰 모델, 실행은 작은 모델"**
  - 작은 과제에서 분리하면 성공 1건당 $1.49였습니다. Sonnet 단독은 $0.23이었습니다.
  - 계획을 좁혀도 $0.30으로, 여전히 27% 비쌌습니다.
  - 그래서 기본은 끔입니다. 큰 과제에서는 아직 재지 않았습니다.
- 원문: [ADR-055](decisions.md#adr-055-도구-결과에-예산을-두고-토큰-사용을-턴-단위로-보인다) · [ADR-064](decisions.md#adr-064-에이전트는-게이트가-하는-확인을-되풀이하지-않는다자가-확인-lean을-기본으로) · [ADR-075](decisions.md#adr-075-계획은-큰-모델로-한-번-세우고-실행은-작은-모델로-한다) · [E6](experiments/2026-09-30-e6-token-breakdown.md) · [E7](experiments/2026-09-30-e7-lean-self-check.md) · [E8](experiments/2026-09-30-e8-plan-execute-split.md) · [E9](experiments/2026-10-01-e9-narrow-plan.md)

## 9. 코어는 도메인을 모르게, 거짓 성공 탐지에 집중한다

- **문제**: 웹에 특화할지, ML·데이터에 특화할지, 중립으로 둘지가 열려 있었습니다.
  - 조사해 보니 깊은 검증은 스택을 고정한 웹 빌더에만 있었습니다.
  - 거짓 성공은 도메인과 무관했습니다. METR RE-Bench에서는 128회 중 39회 점수 코드를 조작했습니다. b-studio에서는 E1의 거짓 성공 5건이 있었고, E15에서는 틀린 테스트를 건네자 18/18 통과했습니다.
- **버린 것**
  - 웹 전용: 상용 빌더와 겹칩니다.
  - ML 전용: GPU, 정답 지표, 레퍼런스가 없습니다.
- **고른 것**: 코어는 중립으로 두고, 깊은 레퍼런스는 웹 하나만 둡니다. 다른 도메인은 얇은 검증 묶음으로 붙입니다.
  - 코어에서 키울 것은 거짓 성공 탐지입니다. 평가 자산은 보호 경로로 두고, 에이전트가 보고한 숫자는 게이트가 다시 계산한 값으로만 판정합니다.
- **결과**: 파이프라인 정의(Argo·Airflow·쿠버네티스·Helm) 묶음에 오류 8종을 넣었습니다. 각 오류가 해당 검사에서만 걸렸습니다.
- 원문: [ADR-175](decisions.md#adr-175-코어는-도메인을-모르게-두고-깊게-지원하는-레퍼런스는-웹-하나-다른-도메인은-얇은-검증-묶음으로-붙인다)

## 10. 지원 범위를 좁히고 나머지는 실험으로 숨긴다

- **문제**: 기능이 많아져서 무엇이 실제로 쓰이고 확인된 것인지 알 수 없었습니다.
- **고른 것**: 지원 범위를 셋으로 좁혔습니다. 단일 세션, 로컬 CLI 백엔드(Claude Code), 로컬 Docker입니다.
  - [구현 상태](status.md#지원-범위)에는 기능마다 **실제 환경에서 마지막으로 확인한 날짜**를 적습니다. 테스트 통과 날짜가 아닙니다.
  - 나머지 기능(작업 분해, 여러 AI 비교, 다른 백엔드, Kubernetes, 운영 배포, 디자인 비교)은 스위치 하나(`B_STUDIO_EXPERIMENTAL`) 뒤로 숨깁니다.

- **결과**: 작업 규칙도 이 구분을 따릅니다. 실험 경로는 같이 고치지 않고, PR에 "확인하지 않은 경로"를 적습니다.
- 원문: [ADR-166](decisions.md#adr-166-지원-범위를-단일-세션로컬-clidocker로-좁히고-나머지는-실험으로-숨긴다)

## 11. 화면은 터미널 하나, 관문은 CLI 훅

- **문제**: 2026-10-23에 웹 대시보드를 써 본 사용자가 말했습니다. "웹 채팅 같다, 내가 말한 것은 터미널이었다." 또 터미널에서 CLI로 한 일은 b-studio가 알지 못해 검증 밖에 있었습니다.
- **고른 것**
  - 웹 화면과 데스크톱 앱을 지웠습니다(#917). 화면은 터미널 작업대 `studio desk` 하나입니다. 서버 로직은 그대로 두고, 보이는 것만 터미널로 옮겼습니다.
  - 터미널의 CLI(Claude Code·Codex)는 CLI 본래 사용법 그대로 씁니다. b-studio는 CLI의 공식 훅(요청 시작·도구 실행 직전·턴 끝)으로 요청을 잡고, 턴 끝에서 게이트를 돌립니다. 통과하면 체크포인트를 남기고, 실패하면 결과를 에이전트에게 돌려줍니다.
- **버린 것**
  - 터미널 출력을 읽어 짐작하기: 화면 모양이 바뀌면 깨집니다.
  - 작업 복사본 변화만 감시하기: 언제 끝났는지 모릅니다.
  - 웹을 터미널처럼 꾸미기
- **한계(원문)**: 훅 연결은 진짜 CLI와 가짜 모델로 확인했습니다. 실제 모델 세션으로 돌린 기록은 [실험 기록](experiments/README.md)에 따로 있습니다.
- 원문: [ADR-186](decisions.md#adr-186-웹-화면을-버리고-터미널-하나studio-desk를-유일한-화면으로-삼는다) · [ADR-170](decisions.md#adr-170-터미널의-요청은-cli의-훅으로-잡아-게이트와-체크포인트에-잇고-통과하지-못하면-대화-창처럼-되돌린다) · [ADR-173](decisions.md#adr-173-세션-터미널을-이-컴퓨터의-cli로도-연다-사용자의-로그인-셸에서-띄우고-훅은-실행-인자로-붙인다)

## 12. 백엔드를 Rust로 옮긴다: 차등 시험으로 한 조각씩

- **왜**: 끝 모양은 Node 없는 실행 파일 하나입니다. 또 막는 검사를 타입으로 강제하려는 목적이 있습니다. 경로 검사의 틈 세 개(트러블슈팅 124~126)가 모두 "문자열 비교가 파일 시스템과 다르게 읽은" 꼴이었습니다.
- **버린 것**
  - Rust 사이드카: 프로세스 경계가 "다르게 읽는 자리"를 하나 더 만듭니다.
  - 한 번에 새로 쓰기: 그동안 기능 개발이 멈추고, 견줄 기준도 없습니다.
- **고른 것**: 순수 Rust 크레이트를 napi로 붙여 모듈 단위로 바꿉니다.
  - 순서는 막는 검사 → 샌드박스 → 에이전트 → 서버입니다.
  - 옮기는 PR에서 TS 구현을 지웁니다. 그 전에 옛 TS와 새 Rust에 같은 입력을 넣는 **차등 시험**과 **변이 시험**으로 같음을 확인합니다.
  - 서버는 Rust 앞단(axum)이 공개 포트를 쥐고, 아직 옮기지 않은 경로는 유닉스 소켓의 Node 자식에게 넘깁니다.
- **결과**
  - 1단계: 무작위 입력 35만 개를 6종 함수에 넣어 결과 210만 쌍을 비교했고, 다른 결과는 0이었습니다.
  - 인증 판단: 옛 TS가 진짜 `node:http` 안에서 낸 판단 6305개와 견줘 앞단이 더 막은 것 0, 더 연 것 0이었습니다.
  - "가벼워졌다"는 말은 이전이 끝나고 다시 잴 때까지 쓰지 않기로 했습니다.
- **진행**: 진행 중입니다. 단계별 상태는 [ADR 지도](adr-map.md#rust-이전)와 ADR-195·199의 덧붙임에 있습니다.
- 원문: [ADR-191](decisions.md#adr-191-백엔드는-rust로-단계적으로-옮긴다-순수-rust-크레이트를-napi로-붙이고-옮긴-pr에서-ts-구현을-지운다) · [ADR-194](decisions.md#adr-194-claude-code-러너는-agent-sdk-대신-공개-cli-입출력stream-json으로-돈다) · [ADR-195](decisions.md#adr-195-4단계-rust-서버를-앞에-두고-옮기지-않은-경로는-node로-넘긴다-인증을-옮기기-전에는-공개-경로만-직접-처리한다) · [ADR-199](decisions.md#adr-199-화면-확인-러너를-rust-cdp로-옮긴다-파이프로-chromium을-직접-말하고-출처-제한-두-층은-같은-판정으로-옮긴다)
