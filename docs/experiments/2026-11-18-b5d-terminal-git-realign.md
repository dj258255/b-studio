# 실측: Git 맞추기를 코어로 옮긴 뒤 요청 사이의 커밋과 브랜치 바꾸기 (2026-11-18)

[ADR-218](../decisions.md), 이슈 #1293. B5d에서는 Git 맞추기 판정과 되돌리기 조합 순서를 Rust 코어로 옮겼습니다. 같은 PR에서 바꾼 것은 넷입니다.

- 풀거나 되돌린 뒤 끝 상태를 다시 읽어 확인합니다.
- 내 폴더 세션에서 남긴 에이전트 변경을 "직접 수정"으로 커밋하지 않습니다.
- 읽기만 요청이 위반으로 끝나면 문서까지 되돌립니다.
- 직접 수정 커밋은 파일 이름을 글자 그대로 읽습니다.

이 실측은 바뀐 고리를 거쳐도 사람이 요청 사이에 작업 복사본의 Git을 건드렸을 때의 평소 동작이 그대로인지 봅니다. 평소 동작은 둘입니다. 직접 커밋은 풀어서 검증하고, 브랜치를 바꾼 것은 되돌립니다.

## 환경

- **기기와 CLI**: macOS arm64, 실제 Claude Code CLI 2.1.326(구독 로그인)
- **세션 방식**: 이 컴퓨터 방식 세션 터미널. 실험 스위치를 끈 서버로 띄웠습니다.
- **세션 모델**: `haiku`
- **코드**: 브랜치 `feat/b5d-git-realign-revert`(1a6448a)
- **서버**: 실측 전용 폴더와 3923번 포트로 띄웠습니다.
- **하네스**: `measure-term.mjs realign`(이번에 더함). 프로젝트는 vf3이고 복사본 세션입니다.
  - 요청마다 README 첫 줄만 읽게 합니다.
  - 요청과 요청 사이에 하네스가 작업 복사본에서 직접 `git`을 부릅니다.
