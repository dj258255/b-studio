# B4b 실측: 세션 터미널의 요청 시작·쓰기 직전 판정을 코어로 옮긴 뒤 (2026-11-16)

[ADR-211](../decisions.md), 이슈 #1278. 이 PR이 바꾼 것은 세 가지입니다. 요청 시작(UserPromptSubmit)·쓰기 직전(PreToolUse)·b-studio 도구(MCP) 판정을 Rust 코어의 순수 판정으로 옮겼습니다. 쓰기 직전 훅과 MCP는 기다림(샌드박스 켜기·보호 경로 고정) 뒤에 같은 판정을 다시 부릅니다. 터미널 요청은 점유를 먼저 잡고 준비합니다. 여기서는 이 변경 뒤에도 지원 경로의 기본 흐름(요청 → 쓰기 → 게이트 통과, 읽기만 거절)이 실제 CLI에서 그대로 도는지 봅니다.

## 환경

- macOS arm64, Node 22.17, 로컬 Docker(Colima)
- 실제 Claude Code CLI(구독 로그인), 이 컴퓨터 방식 세션 터미널(기본값), 실험 스위치 없는 서버
- 서버: 브랜치 `feat/b4b-terminal-prompt-pretool`(d952d0d)를 실측 전용 폴더(`~/.cache/b-studio/real4`)와 3923번 포트로 띄웠습니다. 네이티브 모듈은 커밋된 Rust와 같은 빌드입니다(빌드 뒤에 바뀐 `.rs`가 없음을 확인했습니다).
- 프로젝트: `vf3`(정적 `index.html` + `order.json`, HTTP·브라우저 화면 확인)
- 하네스: 세션 터미널 API로 desk 대신 CLI를 몹니다(`measure-term.mjs`, B4a에서 만듦). 이번에 `pass`·`readonly` 시나리오를 더했습니다. 세션을 만들고, 터미널을 열고, 폴더 신뢰 창에 답하고, 실행이 끝나기를 기다립니다. 그다음 바뀐 파일을 보고, 다음 요청이 새 실행으로 열리는지 봅니다. 마지막으로 세션을 멈추고 지웁니다.

## 보지 못한 것

- **P1~P3를 실제 세션에서 일으키지 않았습니다.**
  - P1(켜기를 기다리는 사이 `[읽기만]`이 이어 오거나 턴 상한에 닿음): CLI는 훅의 답을 기다리는 동안 다음 요청을 훅으로 보내지 않습니다. 실제 세션에서 이 둘을 겹치게 할 수 없었습니다.
  - P2(준비 중 다른 실행이 점유를 잡음), P3(도구가 연 실행이 허용을 가져감): 때를 맞추기가 같은 이유로 어렵습니다.
  - 셋 다 가짜 샌드박스 시험(`sessions-terminal-prompt.test.ts`)으로만 확인했습니다.
- **병렬 도구 호출:** 열린 실행 없이 병렬 도구 호출이 오면 두 번째가 바쁨으로 거절됩니다(ADR-211 결정 4). 실제 세션에서 이 길에 닿는지는 재지 않았습니다.
- **MCP 도구:** b-studio 도구(MCP)를 쓰는 요청은 이번 실측에 넣지 않았습니다.
- **desk 화면:** 보지 않았습니다.
- **고치기 전 코드:** 같은 실측을 하지 않았습니다. 두 시나리오는 고치기 전에도 같은 결과일 흐름이라, 이번 실측은 결함 재현이 아니라 회귀가 없는지 보는 확인입니다.
