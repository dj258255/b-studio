# 실측: 세션 지우기·이어받기의 폴더를 세션을 읽어 온 폴더로 정한 뒤 실제 세션의 지우기, 복구 뒤 지우기, 고친 저장 파일 거절 (B2a)

- 날짜: 2026-11-16(12:46~12:55 KST)
- 관련: 이슈 #1257(추적 #1255), 브랜치 `feat/b2a-session-delete-guard`, [ADR-204](../decisions.md)
- 환경: macOS arm64, 로컬 Docker(Colima)
  - 이 브랜치의 worktree에서 `B_STUDIO_EXPERIMENTAL`·`B_STUDIO_TERMINAL`을 지운 셸로 `pnpm studio launch --mode local --port 3923`을 실행했다.
  - 세션 폴더는 실측 전용 `B_STUDIO_SESSIONS_DIR`이다. 프로젝트는 `vf3`(정적 웹 서비스 하나), 백엔드는 `claude-code`, 작업 공간은 작업 복사본(`copy`)이다.
  - 하네스(`~/.cache/b-studio-ship/real4/h5/measure-b2a.mjs`)는 화면 없이 API만 부른다. 만들기·켜기(`boot`)·멈추기(`DELETE /api/sessions/:id`)·지우기(`POST …/delete`)·이어받기(`POST …/resume`)를 부르고, 폴더가 남았는지 디스크에서 본다.
  - 모델은 부르지 않았다. 세션을 켜고 멈추기만 했다.
- 한 번씩 잰 값이다.

## 무엇을 보려 했나

이 브랜치에서 지울 폴더와 이어받을 폴더는 저장 파일의 `workDir`·`stateDir` 글자가 아니라 세션을 만들거나 읽어 온 폴더(`home`)다. 판정과 지우기는 Rust `lifecycle`이 한다. 실제 세션에서 다음을 본다.

- 정상 세션의 지우기가 옛 판처럼 되는가: 지연 기동(`idle`) 세션, 켜고 멈춘 세션, studio를 다시 띄운 뒤 복구된 세션
- 저장 파일을 고쳐 다른 세션의 폴더나 링크 너머의 저장소 밖을 가리키게 하면 지우기와 이어받기가 거절되고 그 폴더가 남는가

## 결과

- **지연 기동 세션 지우기:** 만들면 `idle`이었다(지연 기동). 그대로 지우니 200이었고 폴더가 없어졌다.
- **만들기 → 켜기 → 멈추기 → 지우기(`d6a33ec2`)**
  - `boot` 202 뒤 `ready`, 멈추기 200 뒤 `stopped`였다.
  - 지우기는 200이었다. 폴더 `vf3-d6a33ec2`가 없어졌고 `GET /api/sessions/:id`는 404였다.
- **studio를 내렸다 띄운 뒤 복구된 세션 지우기(`151f8042`):** 세션 넷(B·C·D·E)을 켜고 멈춘 뒤 studio를 내렸다 띄웠다. 넷 모두 `stopped`로 복구됐다. B를 지우니 200이었고 폴더가 없어졌다.
- **고친 저장 파일: 다른 세션의 폴더(C → D)**
  - studio를 내린 동안 C(`f0ded6a0`)의 `snapshot.workDir`을 D(`ee6f9eaa`)의 폴더로 고쳤다.
  - 지우기는 500 "삭제할 폴더가 세션 저장소 밖에 있거나 이 세션의 폴더가 아닙니다: …/vf3-ee6f9eaa"였다. C와 D의 폴더가 둘 다 남았다.
  - 이어받기는 409 "저장 파일이 가리키는 폴더가 이 세션의 폴더와 달라 이어서 작업하지 않았습니다. …"였다. D의 폴더가 남았다.
  - 옛 판에서는 이 지우기가 D의 폴더를 지운다. 이 브랜치의 `sessions-home-guard.test.ts`가 고치기 전 코드에서 확인했다.
- **고친 저장 파일: 링크 너머의 저장소 밖(E)**
  - 저장소 밖(`real4/outside-b2a/inner`)에 git 저장소와 커밋하지 않은 파일(`precious.txt`), 표시 파일(`marker.txt`)을 만들었다.
  - E(`b8517e4d`)의 폴더 안에 그 폴더를 가리키는 링크 `link`를 놓고 `workDir`을 `<E 폴더>/link/inner`로 고쳤다.
  - 지우기는 500(같은 글), 이어받기는 409(같은 글)였다. 두 파일이 모두 남았다.
  - 옛 판에서는 지우기가 `inner`를 지우고, 이어받기가 `precious.txt`를 버린다. 이 브랜치의 시험이 고치기 전 코드에서 확인했다.
- **정상으로 되돌린 뒤:** C가 가리키던 D는 그대로 지워졌다(200). studio를 내리고 C·E의 저장 파일을 고치기 전 사본으로 되돌린 뒤 링크를 치웠다. 다시 띄우자 C·E 모두 200으로 지워졌고 폴더가 없어졌다. 이 실측이 만든 세션 폴더(아래 F 포함 일곱 개)는 모두 지워졌다.

- **세션 폴더 안에 링크를 둔 채 지우기(`4c66d68a`, 12:55 KST):** 켜고 멈춘 세션 폴더 안에 저장소 밖을 가리키는 링크 둘(`link-out` → 바깥 폴더, `.git/link-inner` → 그 안의 `inner`)을 놓고 지웠다. 200이었고 세션 폴더는 없어졌으며 바깥의 `marker.txt`는 남았다. 링크만 지워지고 너머는 따라가지 않았다.

## 보지 못한 것

- 내 폴더(`local`) 세션은 실제로 지우거나 이어받지 않았다. 상태 폴더만 지우고 사용자 폴더는 남기는 것은 시험으로만 확인했다.
- 확인과 지우기 사이에 폴더를 링크로 바꾸는 경합은 실제 세션에서 만들지 않았다(Rust 시험의 틈으로 확인).
- 호스트의 CLI가 세션 터미널에서 실제로 `session.json`을 고칠 수 있는지는 해 보지 않았다. 이번에는 studio를 내린 동안 하네스가 고쳤다.
