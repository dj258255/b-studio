# 실측: API 오류로 끝난 턴의 실행 닫기 (2026-11-18)

[ADR-214](../decisions.md), 이슈 #1284. 결함은 [B4d 실측](2026-11-18-b4d-terminal-usage-real.md)에서 처음 봤습니다. 구독의 주간 사용 한도에 닿아 턴이 끝났는데, 실행이 열린 채 남았습니다.

여기서는 같은 결함을 일부러 다시 일으켜, 고치기 전과 고친 뒤를 비교합니다.

## API 오류를 일으킨 방법

- 사용 한도는 이 실측을 하기 전에 이미 풀려 있었습니다. 같은 하네스로 고치기 전 코드를 돌리자 턴이 정상으로 끝났습니다(`done`, 체크포인트). 그래서 사용 한도로는 다시 일으킬 수 없었습니다.
- 대신 claude-code 백엔드가 세션의 모델 id를 검사하지 않는다는 점을 썼습니다(`newSessionModel`). 세션을 없는 모델 `claude-measure-nonexistent-1`로 만들면, 이 컴퓨터 방식 터미널이 CLI를 `--model=claude-measure-nonexistent-1`로 띄웁니다.
- CLI는 "There's an issue with the selected model … It may not exist"를 띄우고 턴을 끝냅니다. 오류 종류는 `model_not_found`입니다.
- 이 방법은 본 요청의 토큰을 쓰지 않습니다. CLI 안의 작은 모델(haiku) 호출 하나만 기본 모델로 나갑니다.

  - 실제 Claude Code CLI 2.1.326, 구독 로그인
  - 이 컴퓨터 방식 세션 터미널, 실험 스위치가 꺼진 서버
- **코드**
  - 고치기 전: main a15d5fb을 임시 worktree에서 띄웠습니다.
  - 고친 뒤: 브랜치 `fix/terminal-stop-failure`(6d81367)
- **서버**: 실측 전용 폴더와 3923번 포트로 띄웠습니다. 네이티브 모듈은 각자 빌드했습니다.
- **하네스**: `measure-term.mjs api-error`. 요청은 `README.md` 끝에 한 줄을 더하라는 것이고, `MEASURE_MODEL` 환경 변수로 세션 모델을 정합니다.

## 보지 못한 것

- **바뀐 파일을 되돌리는 칸**: 이 방법으로는 첫 모델 호출에서 턴이 끝나 바뀐 파일이 없었습니다. 되돌리기는 시험으로만 확인했습니다. Edit 뒤에 API 오류가 나는 순간을 실제로 맞추려면 실제 사용 한도나 과부하가 필요합니다.
- **사용 한도(`rate_limit`)로 오는 훅의 모습**: 실제로는 보지 못했습니다. 이번 실측에서는 `model_not_found`로 같은 훅이 오는 것만 봤습니다.
- **desk 화면**: 보지 않았습니다.
- **반복**: 고치기 전과 고친 뒤를 한 번씩만 돌렸습니다.
