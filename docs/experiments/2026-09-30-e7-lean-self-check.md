# 실험 E7: 자가 확인 lean은 토큰을 줄이면서 성공을 유지하는가

- 날짜: 2026-09-30 (KST 01:16 ~ 02:39)
- 관련 이슈: [#193](https://github.com/dj258255/b-studio/issues/193)(사전 등록), 기능 [#192](https://github.com/dj258255/b-studio/issues/192), 근거 [E6](2026-09-30-e6-token-breakdown.md)
- 커밋: [e9d8744](https://github.com/dj258255/b-studio/commit/e9d8744). 두 조건 모두 이 커밋을 고정한 작업 트리에서 돌렸습니다.
- 원자료: `~/.cache/b-studio/bench/coordination/e7-{full,lean}-r{1,2,3}/`. 18행의 핵심 열은 [`data/2026-09-30-e7-results.csv`](data/2026-09-30-e7-results.csv)에 옮겼습니다.

## 왜 이 실험인가

E6에서 b-studio(S0)가 그냥 Claude Code(P0)보다 더 쓴 문맥의 78%는 도구 결과를 다시 읽은 양이었습니다. 가장 큰 것은 `run_in_service`(32.7%)였습니다.

원인은 시스템 프롬프트로 봤습니다.
- 프롬프트는 "빌드·테스트를 돌리고 끝내기 전에 확인하라"고 권합니다.
- 그런데 게이트도 턴을 끝내면 같은 확인을 합니다.

그래서 lean 모드를 만들었습니다([#194](https://github.com/dj258255/b-studio/pull/194)).
- 프롬프트가 게이트와 겹치는 확인을 하지 말라고 안내합니다.
- 성공한 명령의 출력은 800자만 돌려줍니다. 실패한 명령은 그대로입니다.

## 가설 (실행 전에 [#193](https://github.com/dj258255/b-studio/issues/193)에 적음)

- **H15**: E7-lean의 성공 1건당 토큰은 E7-full보다 25% 이상 적다.
- **H16**: E7-lean의 성공은 E7-full과 구별되지 않는다(차이 1건 이하).
- 설명용: lean에서 모델 호출 수와 `run_in_service` 재읽기 몫이 줄어든다. 게이트 재시도는 늘 수 있다.

## 결론

- **H15: 추정치는 기준을 넘었지만, 통계적으로는 확인되지 않음**
  - 성공 1건당 토큰은 41.4% 적어 가설의 기준(25%)을 넘었습니다.
  - 짝지은 비교는 p = 0.164로, 9쌍으로는 우연과 구별되지 않습니다. 과제 하나(order-summary)는 반대 방향이었습니다.
  - E5에서 본 것처럼 같은 설정 안의 편차가 커서, 9회로는 이 크기의 차이도 확정하기 어렵습니다.
- **H16 확인**: 성공은 9/9 대 9/9입니다(p = 1.0). 게이트 실패도 늘지 않았습니다(0건 대 0건).
- **무엇이 줄였나**
  - 대부분 **성공한 명령 출력 줄이기**에서 나왔습니다. `run_in_service`는 호출이 오히려 늘었지만(71 → 83), 결과 글자가 69% 줄어 재읽기가 77% 줄었습니다.
  - 프롬프트 안내는 끝난 변경을 확인하는 호출을 없앴습니다(`http_request` 19 → 0, `service_logs` 6 → 0, `restart_service` 26 → 16). 하지만 명령 실행 자체는 줄이지 못했습니다.
  - 두 변경을 한 설정으로 묶어서, 각각의 몫을 따로 판정하지는 못합니다. 위 분해는 몫을 설명하는 근거일 뿐입니다.
- **그냥 Claude Code와의 차이**: lean의 성공 1건당 토큰(24.9만)은 E6의 P0(20.1만)와 가까워졌습니다. 다른 날의 다른 실험이라 직접 비교는 아닙니다.

## 결정에 주는 영향

- **ADR-064**: 스튜디오의 기본 자가 확인 범위를 lean으로 바꿉니다. `B_STUDIO_SELF_CHECK=full`이면 이전 동작입니다.
  - 근거: 성공과 게이트 실패가 같았고, 토큰 추정치는 41% 적었으며, 큰 쪽 꼬리가 사라졌습니다.
  - 되돌리기도 쉽습니다(설정 하나).
- 벤치 기본은 full로 둡니다. E1~E7과 같은 조건으로 비교하기 위해서입니다.
- 기본값으로 쓰면서 계속 볼 것이 두 가지 있습니다.
  - 게이트 시간이 늘어난 대가: 레인 게이트 합 +64%, 종단 시간은 −4%
  - 과제가 커져 에이전트의 자가 확인이 실제로 실패를 먼저 잡던 경우가 사라지는지

이 결론은 이 저장소의 예제(Spring Boot api와 Next.js web), 작은 과제 3개, 조건별 9회에서만 확인했습니다.
