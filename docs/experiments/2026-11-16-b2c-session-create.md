# 실측: 세션 만들기의 순서를 Rust 수명 코어로 옮긴 뒤 실제 세션의 만들기, 켜기 실패 뒤 다시 켜기, 폴더를 만든 뒤 실패한 만들기의 치우기 (B2c)

- 날짜: 2026-11-16(17:44~17:47 KST)
- 관련: 이슈 #1261(추적 #1255), 브랜치 `feat/b2c-session-create`, [ADR-206](../decisions.md)
- 환경: macOS arm64, 로컬 Docker(Colima)
  - 이 브랜치의 worktree에서 `B_STUDIO_EXPERIMENTAL`·`B_STUDIO_TERMINAL`을 지운 셸로 `pnpm studio launch --mode local --port 3923`을 실행했다(인증 `none`).
  - 세션 폴더는 실측 전용 `B_STUDIO_SESSIONS_DIR`이다. 작업 복사본 세션은 프로젝트 `vf3`(정적 웹 서비스 하나)로 만들었다.
  - 실패를 만들려고 `PATH` 앞에 docker 감싸개(`~/.cache/b-studio-ship/real4/wrap2/docker`)를 두었다. 표시 파일이 있을 때만 `compose up` 또는 `compose config`를 한 번 실패시키고, 나머지는 실제 docker로 넘긴다.
  - 하네스(`~/.cache/b-studio-ship/real4/h5/measure-b2c.mjs`, `measure-b2c-create.mjs`)는 화면 없이 API만 부르고 세션 저장소 폴더 목록을 직접 읽는다.
  - 모델은 부르지 않았다.
- 한 번씩 잰 값이다.

## 무엇을 보려 했나

이 브랜치에서 세션 만들기의 단계 순서와 실패 처리는 Rust 수명 코어가 정한다. 실제 세션에서 다음을 본다.

- 만들기(지연 기동)가 옛 판처럼 `idle` 세션과 저장 파일을 남기는가
- 켜기가 실패하면 `failed`로 끝나고 폴더가 남으며, 다시 켜면 `ready`가 되는가(켜기 규칙은 B2b 그대로)
- 세션 폴더를 만들고 작업 복사본을 복제한 **뒤에** 만들기가 실패하면 그 폴더가 지워지고 목록에 남지 않는가

## 결과

- **만들기와 켜기 실패 뒤 다시 켜기(`63950a67`)**
  - 만들기 201, 상태 `idle`, 세션 폴더와 `.git/b-studio/session.json`이 있었다.
  - 감싸개로 `compose up`을 한 번 실패시키고 켜니 502 "샌드박스를 켜지 못했습니다: docker compose up 실패 (…)"였고 상태는 `failed`였다. 폴더는 남았다(켜기 실패는 만들기 실패가 아니라 세션을 지우지 않는다. 옛 판과 같다).
  - 다시 켜니 202 → `ready`였다.
  - 멈추기 200, 지우기 200 뒤에 폴더가 없었다.
- **폴더를 만든 뒤 실패한 만들기**
  - 감싸개로 `compose config`를 한 번 실패시켰다. 이 명령은 `provider.create`의 git 가림 준비(`loadGitMask`)가 부르므로, 세션 폴더 만들기와 작업 복사본 복제가 끝난 뒤에 실패한다.
  - 만들기는 500 "compose 설정을 읽지 못해 서비스 컨테이너의 .git 보호를 정할 수 없습니다"였다(제공자의 오류 글이 그대로 나온다).
  - 만드는 동안 0.1초마다 세션 저장소를 읽었더니 `vf3-a0171b22`가 생겼다가 사라졌다. 끝난 뒤 세션 저장소의 폴더 수는 19 → 19였고, 세션 목록에도 그 세션이 없었다.
  - 옛 판은 같은 실패에서 이 폴더를 남긴다. `sessions-create-failure.test.ts`(샌드박스 만들기 실패 사례)가 고치기 전 코드에서 확인했다. 실제 studio에서 옛 판을 띄워 다시 재지는 않았다.
- **형식이 틀린 프로젝트로 만들기**
  - 폴더를 연 뒤 원본의 `studio.yaml`을 망가뜨리고 만들기를 했더니 404 "프로젝트를 찾을 수 없습니다"였다. 세션 폴더를 만들기 전에 프로젝트 목록에서 빠져서다. 세션 저장소의 폴더 수는 19 → 19였다.
  - 이 사례는 세션 폴더를 만든 뒤의 실패가 아니라서 치우기를 확인하지 않는다. 그래서 위의 `compose config` 실패를 더했다.

## 보지 못한 것

- 즉시 기동(만들면서 바로 켜기)은 실제 studio에서 재지 않았다. HTTP 만들기(`POST /api/sessions`)는 늘 지연 기동이고, 즉시 기동은 플릿·작업 분해(실험 기능)만 쓴다. 즉시 기동은 차등 시험이 확인한다.
- 맵에 넣은 뒤의 실패(미리보기 게이트웨이를 만들지 못함 등)는 실제 환경에서 만들 길이 없어 가짜 제공자 시험으로만 확인했다.
- 내 폴더 세션의 만들기 실패(상태 폴더 치우기, 사용자 폴더 보존)는 실제 studio에서 재지 않았다(시험으로만).
- 실측에 쓴 `real4/src/brk` 폴더와 프로젝트 등록은 실측 저장소에 남겨 두었다.
