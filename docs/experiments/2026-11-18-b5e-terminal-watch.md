# 실측: 감시를 코어로 옮긴 뒤 훅 없는 CLI·관문 파일 변조·첫 요청 글의 --settings (2026-11-18)

[ADR-219](../decisions.md), 이슈 #1295. B5e는 이 컴퓨터 방식 세션 터미널의 감시(위반 감지)와 훅 본문 해석을 Rust 코어로 옮겼습니다. 같은 PR에서 감시 동작 다섯 가지를 바꿨습니다.

- 살아 있는 위반은 새로 연 실행에도 다시 적습니다.
- 턴 끝은 감시를 믿을 수 있는지 묻고, 믿을 수 없으면 통과로 닫지 않습니다.
- 터미널 pid를 모르면 "검사할 수 없음"으로 둡니다.
- 쓰기 직전 훅과 요청 시작 훅은 읽지 못한 본문을 거절합니다.
- 훅이 붙었는지는 `ps` 한 줄이 아니라 프로세스의 진짜 argv로 판정합니다.

이 실측은 고치기 전 코드(main c600150)와 고친 코드에서 같은 시나리오를 돌려 견줍니다.

## 환경

- **기기와 CLI**: macOS arm64, 실제 Claude Code CLI 2.1.326(구독 로그인)
- **세션**: 이 컴퓨터 방식 세션 터미널. 실험 스위치를 끈 서버로 띄웠고, 모델은 `haiku`입니다.
- **프로젝트**: vf3, 복사본 세션
- **서버**: 실측 전용 폴더와 3923번 포트로 띄웠습니다.
- **코드**: 고치기 전은 c600150입니다. 고친 뒤는 dcaf1fd와 05b9c8b에서 각각 돌렸습니다.
- **하네스**: `measure-term.mjs`에 `unhooked`, `tamper`, `settings-word`를 더했습니다.
- **훅 없는 CLI**: 실제 모델을 부르지 않는 가짜를 썼습니다. 실측 폴더에 `/bin/sleep`을 가리키는 `claude` 링크를 두고, 세션 안 CLI가 Bash 도구의 백그라운드 실행으로 그것을 띄우게 했습니다.
  - 프로세스 나무는 `claude CLI → /bin/zsh -c … → …/fake/claude 90`입니다.
  - 감시는 첫 낱말의 파일 이름이 `claude`라 CLI 후보로 보고, 감싸개가 붙이는 설정이 없어 위반으로 봅니다.

## 결과

### 훅 없는 CLI가 계속 도는 동안 (`unhooked`)

가짜 CLI를 띄운 실행 A가 끝나면 같은 터미널에서 B를 보냅니다. 그 뒤 가짜를 끄고 C를 보냅니다. 고치기 전 코드에서는 가짜를 끄지 않은 채 C를 보냈습니다.

| | 고치기 전(c600150) | 고친 뒤(05b9c8b) |
|---|---|---|
| A(가짜를 띄움) | 약 17초 뒤 `failed` "검증이 붙지 않은 CLI가 터미널에서 돌고 있습니다(pid …)" | 같음 |
| B(가짜가 살아 있음) | **`done`**, Edit가 체크포인트로 남음 | `failed`, 같은 사유 |
| C | 가짜가 살아 있는데도 **`done`** | 가짜를 끈 뒤 `done`(오탐 없음) |

고치기 전에는 한 번 알린 위반을 그 뒤 실행이 몰랐습니다(트러블슈팅 264). 고친 뒤에는 살아 있는 동안 연 실행이 모두 닫혔고, 사라진 뒤에는 정상으로 돌아왔습니다. dcaf1fd에서도 같은 결과였습니다.

### 관문 파일 변조 (`tamper`)

첫 실행이 끝난 뒤 하네스가 이 세션의 관문 `settings.json` 끝에 빈칸 하나를 더했습니다.

| | 고치기 전(c600150) | 고친 뒤(dcaf1fd) |
|---|---|---|
| 감지 | 0.6초 뒤 "관문 파일이 바뀌어 되돌렸습니다: settings.json" | 같음 |
| B | `failed`, 같은 사유(담아 둔 위반을 가져감) | 같음 |
| C | `done`(파일이 되돌려졌으므로 맞음) | 같음 |

기존 경로가 그대로입니다.

### 첫 요청 글에 `--settings` (`settings-word`)

첫 요청 글이 "README.md 끝에 "claude의 --settings 옵션 메모" 한 줄을 Edit 도구로 더해 줘"인 정상 세션입니다. 첫 요청 글은 CLI의 실행 인자로 실립니다.

- dcaf1fd와 05b9c8b 모두 `done`이었습니다.
- 이 바로 앞 단계(fdc4748, `ps` 한 줄의 낱말을 세던 판정)에서는 이 세션이 위반으로 닫힙니다. 시험으로 확인했고, 실제 세션에서는 돌리지 않았습니다(트러블슈팅 269).
- 05b9c8b는 감싸개가 붙이는 정확한 자리(`<cli> --mcp-config M --settings S …`)만 인정합니다. 진짜 CLI의 argv가 그 모양이라는 것을 이 `done`으로 확인했습니다.

정리할 때 세션마다 멈추고 지웠습니다. 세션 폴더, 컨테이너, 네트워크, 볼륨은 남지 않았습니다. 관문 폴더는 CLI를 끈 세션에서 하나 남았습니다(#1296, 이 PR과 무관한 기존 문제).

## 실측 중 만난 것

- **oh-my-zsh 업데이트 질문**
  - 05b9c8b 첫 실측에서 터미널이 사용자의 zsh를 띄우다 oh-my-zsh의 "Would you like to update? [Y/n]"에서 멈췄습니다. CLI가 뜨지 않아 240초 동안 실행이 열리지 않았습니다.
  - desk 화면에서는 사람이 이 질문을 보고 답할 수 있습니다.
  - 실측에서는 사용자의 셸 상태를 바꾸지 않으려고 답하지 않았습니다. 대신 실측 서버에만 `DISABLE_AUTO_UPDATE=true`와 `B_STUDIO_TERMINAL_ENV=DISABLE_AUTO_UPDATE`를 주어 다시 띄웠습니다.

## 보지 못한 것

- **감시를 믿을 수 없는 턴 끝(N17)과 pid를 모르는 터미널(N20)**: 실제로 만들지 못해 시험(가짜 `ps`)으로만 확인했습니다.
- **읽지 못한 훅 본문의 거절(N18)**: 실제 CLI는 정상 JSON만 보냅니다. 관문에 깨진 본문을 직접 보내지 않았습니다.
- **`--` 뒤나 값을 받는 옵션 뒤의 `--settings`**: 시험으로만 확인했습니다.
- **두 번 fork해 부모가 init이 된 훅 없는 CLI**: 시도하지 않았습니다. 이름과 부모로 찾는 방식의 알려진 한계입니다(ADR-219).
- **Linux와 Windows**: 돌리지 않았습니다.
- **desk 화면**: 보지 않았습니다.
