# 실측: 게이트 검증의 조율을 Rust로 옮긴 뒤 실제 Claude Code 세션으로 돌려 보기 (ADR-195 4f A5a)

- 날짜: 2026-11-14
- 관련: 이슈 #1195, 브랜치 `feat/4f-a5a-verify`
- 모델: 이 컴퓨터에 로그인한 Claude Code 2.1.322(Claude Max). 규칙표는 기본값 하나(claude-code, sonnet)
- 환경: macOS, 로컬 Docker(Colima). 이 브랜치의 worktree에서 `pnpm studio launch --mode local --port 3923`(`B_STUDIO_TERMINAL=host`, `B_STUDIO_EXPERIMENTAL=1`, 등록 목록·세션 폴더는 실측 전용 폴더). desk를 PTY(170x48)로 띄우고 `@xterm/headless`로 화면을 글로 찍었다
- 모두 한 번 잰 값이다

## 무엇을 보려 했나

이 브랜치의 `verify.ts`는 `native.verifyRun`(Rust `crates/bstudio-io/src/verify_io.rs`)만 부른다. 실제 세션의 게이트가 그 경로로 재시작 → 준비 확인 → 계약 비교를 돌려 통과와 실패를 옛 동작대로 내는지 본다.

## 프로젝트

busybox:1.37 httpd 하나(`/work`를 내줌). `studio.yaml`에 준비 경로 `/README.md`(30초), 계약 `contract: { extract: /openapi.json }`, 검사 `grep -q shop /work/README.md`. `openapi.json`은 `Order { id, total }` 하나를 가진 OpenAPI 3.0.3 문서다.

## 결과

desk에서 폴더를 열고 요청 셋을 차례로 보냈다. 폴더 신뢰는 실측 세션 폴더에만 했다.

1. **README 한 줄 더하기(통과).** "README.md 끝에 한 줄을 Edit 도구로 더해 줘". Claude가 Edit로 한 줄을 더했고, 게이트가 통과해 체크포인트 `0801780`이 남았다. 체크포인트 커밋에 실린 보고서: `샌드박스 파일 반영 확인: 0.2초`, `web: 재시작 후 준비 완료`, `web 계약: 계약 변경 없음`, `[test] readme-has-shop(통과)`. 상태는 working → verifying → passed → idle·체크포인트 1(요청에서 통과까지 약 1분, 폴더 신뢰 대기 포함).
2. **계약 깨기(실패).** "openapi.json의 Order 스키마에서 total 속성을 Edit 도구로 지워 줘. 게이트가 막으면 되돌리지 말고 멈춰". 게이트가 세 번 모두 `web 계약: ⚠️ 호환 깨짐 property-removed Order.total`로 막았고, 세 번째 실패 뒤 바뀐 파일 1개를 되돌렸다(`openapi.json`에 `total`이 돌아옴). 두 번째·세 번째 시도는 `재시작한 서비스 없음`이었다(파일이 그대로라 다시 띄울 서비스가 없었다).
3. **준비 실패(실패).** "README.md 파일을 지워 줘". 게이트가 `web: 준비 실패 — 30초 안에 준비되지 않았습니다 (마지막 확인: HTTP 404, 컨테이너 running)`로 세 번 막았다. 세 번째 실패 뒤 "되돌릴 변경은 없었고 문서 1개(README.md)는 되돌리지 않고 체크포인트로 남겼습니다"로 끝났고, 세션 git에 `52aa662 지키기: 되돌리기 전에 문서를 체크포인트로 남긴다`가 생겼다(문서를 지키는 기존 정책).

## 본 것 (이 조각과 무관한 기존 동작)

- 2번에서 사람이 삭제를 분명히 요청했는데도 실패 문구가 "요청에 삭제·변경이 명시되지 않았으므로 호환을 깨는 변경은 허용되지 않습니다"였다. 터미널 경로는 게이트를 늘 `allowBreaking: false`로 만들고(`apps/studio/lib/server/sessions.ts`), 터미널에서 호환 깨짐을 허용할 방법이 없다. 문구가 사람의 요청과 맞지 않는다. [#1197](https://github.com/dj258255/b-studio/issues/1197)로 열었다.

## 보지 못한 것

- 지운 파일 때문에 한 번 더 띄우는 경로(트러블슈팅 13)는 실제로 나지 않았다. busybox httpd가 지운 파일을 로그에 남기지 않는다. 차등 시험으로만 확인했다.
- 메모리 초과(OOM), 막힌 외부 접속, 반영 확인 실패, 스펙 오류(`specError`), compose 변경으로 새 부가 서비스 올리기, 꺼 둔 서비스, 취소는 실제로 재지 않았다(차등 시험으로만).
- 실패한 재시작의 로그 꼬리가 보고서에 실리는지는 보지 않았다(httpd가 아무것도 찍지 않았다).
- 다른 러너(codex 등)와 Kubernetes 제공자는 재지 않았다.
