# 실측: 컨테이너 방식 세션 터미널의 한글 입력

- 날짜: 2026-10-27
- 관련 이슈: [#673](https://github.com/dj258255/b-studio/issues/673)의 남은 항목(컨테이너 안 구독 로그인과 한글 입력을 사람이 확인)
- 결정 문서: ADR-169(터미널 통로와 컨테이너), ADR-172(세션 화면의 중심을 터미널로)
- 가설 없는 관찰이다. 모델 호출은 0회다

## 방법

- main `582e66b`의 제품 코드를 그대로 불렀다. `ensureAgentContainer`로 진짜 에이전트 컨테이너(이미지 `node:22-bookworm-slim`, `.git` 가리기, 프로젝트 홈 볼륨, `LANG=C.UTF-8`)를 만들고, `openAgentTerminal`로 `script` 가상 터미널을 `docker exec -i` 파이프로 열었다. 세션 터미널의 컨테이너 백엔드가 쓰는 두 함수다.
- 실측 프로젝트는 파일 두 개(`README.md`, `한글.txt`)짜리 git 저장소다. Docker VM이 홈 아래만 붙일 수 있어 작업 폴더 안에 잠깐 두었다가 지웠다.
- 나온 바이트를 `studio desk`의 칸 해석기(`PaneTerminal`, `@xterm/headless` + Unicode 11)에 그대로 넣어 화면 글과 폭을 봤다.
- 한글을 넣는 셸은 명령을 `exec bash`로 바꿔 열었다. 기본 명령(claude 설치 → claude)은 첫 실행 화면이 선택 화면이라 키를 보내지 않고 화면만 봤다.

## 결과

### 셸(bash, readline)

| 넣은 것 | 화면 | 판정 |
|---|---|---|
| `echo "LANG=$LANG"; locale charmap` | `LANG=C.UTF-8`, `UTF-8` | 됨 |
| `echo 안녕하세요 한글입력` | 그대로 나옴 | 됨 |
| `printf "%s" "가나다" \| wc -m` | `3` | 됨(바이트가 아닌 글자로 셈) |
| `echo 한글` 뒤 백스페이스 한 번 | `한` | 됨(한 글자가 통째로 지워짐) |
| `echo 가나`, 왼쪽 화살표, `다` | `가다나` | 됨(넓은 글자 위 커서 이동) |
| 괄호 붙여넣기로 `echo 붙여넣은 한글 줄` | 그대로 나옴 | 됨 |
| `echo 갈`과 `라짐`을 두 번에 나눠 넣음 | `갈라짐` | 됨 |
| `ls`, `cat 한글.txt` | `README.md  한글.txt`, `주문 목록` | 됨(파일 이름이 이스케이프되지 않음) |
| `printf "가나다abc\|\n"` | `\|` 앞 폭 9칸 | 됨(한글 한 글자 2칸) |

출력 바이트 전체에 깨진 글자(U+FFFD)가 없었다.

### 기본 명령(claude)

- 새 홈 볼륨에서 `@anthropic-ai/claude-code@2.1.296`이 설치되고 첫 실행 화면("Let's get started. Choose the text style …", 미리보기 diff 포함)이 칸 해석기에서 어긋남 없이 그려졌다.
- 선택 화면이라 키를 보내지 않았다. 그래서 로그인 화면과 CLI 입력 칸의 한글은 보지 못했다.

### 코드에서 확인한 것

- 출력: 서버는 터미널 바이트를 base64로 싣고(`session-terminal.ts`), desk는 바이트 그대로 칸 해석기에 넣는다. 여러 바이트 글자가 조각 경계에서 잘려도 해석기가 이어 붙인다.
- 입력: desk는 바깥 터미널의 키를 `setEncoding('utf8')`로 읽어 조각 경계에서 갈라진 글자를 이어 붙이고, 서버에는 글자열로 보낸다. 컨테이너 쪽 쓰기도 글자열이라 바이트가 갈라질 자리가 없다. 입력기의 조합 중 글자는 바깥 터미널이 앱에 보내지 않으므로 desk가 다룰 것이 없다.
- 터미널 SSE를 읽는 desk 클라이언트는 `TextDecoder`의 `stream: true`를 쓴다.

## 남은 것

- 컨테이너 안 구독 로그인: 범수 님 계정의 브라우저 인증이 필요해 하지 않았다. 첫 실행 화면에서 글자 모양을 고르고 로그인하면 된다.
- 로그인한 뒤의 CLI 입력 칸 한글: 위 셸 결과와 칸 해석기가 같으니 깨질 까닭은 보이지 않지만 직접 보지 못했다.
- 3단계(E17을 컨테이너 안 CLI로 다시 돌리기)와 나가는 통신을 edge 프록시 뒤로 옮기기: #673에 적은 대로 로그인을 한 번 본 뒤에 한다. 허용할 주소는 로그인 흐름이 실제로 닿는 곳을 보고 정한다.
- 컨테이너에 까는 CLI는 2.1.296으로 고정되어 있다(호스트는 2.1.310). 올릴 때는 ADR-168대로 가두기를 다시 확인한다.

## 정리

실측이 만든 컨테이너와 홈 볼륨(`b-studio-agent-home-k673-probe`)을 지웠다. 다른 컨테이너는 건드리지 않았다.
