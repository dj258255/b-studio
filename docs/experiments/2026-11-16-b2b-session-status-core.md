# 실측: 세션 상태를 Rust 수명 코어로 옮긴 뒤 실제 세션의 켜기·멈추기·이어받기, 켜는 중 멈추기, 내 폴더 세션의 별칭 경로 점유 (B2b)

- 날짜: 2026-11-16(13:42~13:44 KST)
- 관련: 이슈 #1260(추적 #1255), 브랜치 `feat/b2b-session-stop-resume`, [ADR-205](../decisions.md)
- 환경: macOS arm64, 로컬 Docker(Colima)
  - 이 브랜치의 worktree에서 `B_STUDIO_EXPERIMENTAL`·`B_STUDIO_TERMINAL`을 지운 셸로 `pnpm studio launch --mode local --port 3923`을 실행했다(인증 `none`, 내 폴더 세션 허용).
  - 세션 폴더는 실측 전용 `B_STUDIO_SESSIONS_DIR`이다.
  - 작업 복사본 세션은 프로젝트 `vf3`(정적 웹 서비스 하나)로 만들었다.
  - 내 폴더 세션은 `vf3`을 복사한 `real4/src/clm`과, 그 폴더를 가리키는 링크 `real4/src/clm-alias`를 각각 프로젝트로 열어 만들었다(`POST /api/projects/open`, id `clm`·`clm-alias`).
  - 하네스(`~/.cache/b-studio-ship/real4/h5/measure-b2b.mjs` a·claim·b)는 화면 없이 API만 부르고, 세션의 SSE에서 `status` 이벤트를 시각과 함께 모은다.
  - 모델은 부르지 않았다.
- 한 번씩 잰 값이다.

## 무엇을 보려 했나

이 브랜치에서 세션 상태는 Rust 수명 코어만 든다. 실제 세션에서 다음을 본다.

- 켜기·멈추기·이어받기의 상태 열과 판정이 옛 판과 같은가
- 켜는 중에 멈추면 멈춘 뒤 `ready`가 나오지 않는가. 멈추는 동안의 켜기와 동시 멈추기가 어떻게 끝나는가
- 내 폴더 세션의 폴더 점유가 링크 별칭을 막는가
- studio를 다시 띄운 뒤에도 이어받기가 되는가

## 결과

- **작업 복사본 세션 수명(`b7e47bf1`)**
  - 만들기 201(지연 기동이라 `idle`) → 켜기 202 → `ready` → 멈추기 200 → `stopped` → 이어받기 202 → `ready` → 멈추기 200 → `stopped`
  - 켜진 세션을 다시 이어받으니 409 "샌드박스를 중지한 세션만 이어서 작업할 수 있습니다"였다(옛 글).
  - SSE의 상태 이벤트는 `starting→ready→stopped→ready→stopped`였다. 이어받을 때는 처음 상태가 이미 `starting`이라 다시 알리지 않는다(옛 `startBoot`와 같다).
- **켜는 중에 멈추기(`f3faa153`)**
  - 켜기 요청 뒤 `starting`이 되자마자 멈추기를 보냈다. 50ms 뒤 켜기와 멈추기를 하나씩 더 보냈다.
  - 첫 켜기를 기다리던 요청과 멈추는 동안의 켜기는 둘 다 409 "중지된 세션입니다. 이어서 작업하면 새 샌드박스를 띄웁니다"였다.
    - 옛 판에서 첫 켜기는 502("샌드박스를 켜지 못했습니다")로 끝난다(ADR-205의 의도한 차이 2, 차등 시험이 확인).
  - 멈추기 둘은 모두 200 `stopped`였다.
  - 멈추기를 시작한 뒤 나간 상태 이벤트는 `stopped` 하나였다. 15초 뒤에도 `stopped`였다.
  - 실제 샌드박스는 중지 신호를 받고 켜기를 끝냈다. "켜기가 막 끝나는 순간에 멈추기"를 실제로 맞추지는 못했다. 그 경주는 가짜 샌드박스 시험(`sessions-stop-boot-race.test.ts`)이 만든다.
- **내 폴더 세션의 별칭 경로 점유**
  - `clm`으로 내 폴더 세션 `d9232662`를 만들었다(201, `idle`).
  - 이어서 `clm-alias`(같은 폴더를 가리키는 링크)로 만들기를 하니 409 "이 폴더는 세션 d9232662에서 작업하고 있습니다. 그 세션의 샌드박스를 중지한 뒤 시작하세요"였다.
  - `d9232662`를 지운 뒤 `clm-alias`로 만들면 201이었다(`02d3561f`, 바로 지움).
  - 옛 판은 글자로만 견줘 별칭 세션을 시작한다. 이 브랜치의 `sessions-folder-claim-alias.test.ts`가 고치기 전 코드에서 확인했다. 실제 studio에서 옛 판을 띄워 다시 재지는 않았다.
- **studio를 다시 띄운 뒤**
  - `b7e47bf1`과 `f3faa153`은 `stopped`로 복구됐다.
  - `b7e47bf1`을 이어받으니 202 → `ready`, 멈추기 200 → `stopped`였다. 두 세션을 지우니 200이었다.

## 보지 못한 것

- 켜기가 막 끝나는 순간의 멈추기(위). 실제 샌드박스에서 시각을 맞출 길이 없어 가짜 샌드박스 시험으로만 확인했다.
- 대소문자만 다른 경로의 점유는 실제 studio에서 재지 않았다(시험으로만). 폴더 열기가 경로를 그대로 등록하는지 확인하지 않았다.
- 실측에 쓴 `clm`·`clm-alias` 폴더와 프로젝트 등록은 실측 저장소에 남겨 두었다.
