- 관련: 이슈 #1266(추적 #1265), 브랜치 `feat/b3a-run-claim`, [ADR-207](../decisions.md)
- 환경: macOS arm64, 로컬 Docker(Colima)
  - 이 브랜치의 worktree에서 `B_STUDIO_EXPERIMENTAL`·`B_STUDIO_TERMINAL`을 지운 셸로 `pnpm studio launch --mode local --port 3923`을 실행했다(인증 `none`).
  - 세션 폴더는 실측 전용 `B_STUDIO_SESSIONS_DIR`이다. 세션은 프로젝트 `vf3`(정적 웹 서비스 하나)의 작업 복사본이다.

## 결과

- **지연 기동(`idle`) 세션에서 질문이 도는 동안 지우기(`0864e356`)**
  - 만들기 201(`idle`) → 질문(`intent: ask`) 202. 상태는 `idle`인 채 `running=true`였다(샌드박스를 켜지 않고 CLI가 돈다).
  - 지우기는 409 "실행 중인 세션은 지울 수 없습니다. 먼저 샌드박스를 중지한 뒤 지우세요"였고 폴더가 그대로였다. 옛 판은 이 지우기를 통과시킨다(`sessions-busy-claim.test.ts` "결함 1"이 고치기 전 코드에서 확인, 실제 studio에서 옛 판을 띄워 다시 재지는 않았다).
  - 두 번째 질문은 409 "이전 요청을 처리하는 중입니다".
  - 멈추기 200 → `stopped`, `running=false`. 이어서 지우기 200, 폴더 없음. 8초 뒤에도 폴더가 다시 생기지 않았다.
- **켠 세션의 만들기 요청 중(`f16fb7af`)**
  - 켜기 202 → `ready`, 요청 202.
  - 2.5초 뒤 두 번째 요청 409 "이전 요청을 처리하는 중입니다", 모델 바꾸기 409 "요청을 처리하는 동안에는 모델을 바꿀 수 없습니다".
  - 다른 `runId` 취소 409 "취소할 수 있는 요청이 없습니다. 이미 끝났거나 결과를 저장하는 중입니다".
  - 취소 202, 곧바로 같은 취소를 한 번 더 보내도 202(이미 취소 중이면 조용히 돌아온다, 옛 판과 같다).
  - 실행이 끝나 `running=false`가 된 뒤 새 질문 202(점유가 풀렸다).
- **멈추는 중 요청(같은 세션)**
  - 멈추기를 보내고 0.3초 뒤 상태는 아직 `ready`였다. 그때 보낸 질문은 409 "중지된 세션입니다. 이어서 작업하면 새 샌드박스를 띄웁니다"였다. 옛 판은 이 요청을 받는다(`sessions-busy-claim.test.ts` "결함 2 요청").
  - 멈추기 200 → `stopped`, 지우기 200, 폴더 없음.

## 보지 못한 것

- 취소한 요청의 끝 결과 글(되돌리기)은 하네스가 스냅샷의 엉뚱한 필드를 읽어 남기지 못했다. 세션을 지운 뒤라 다시 읽지 못했다. 취소와 되돌리기의 결과는 F0 기준 사진(`cancel-revert`)이 고정한다.
- 기준 브랜치 따라잡기·읽기 전용 터미널 실행 시작의 틈(트러블슈팅 219·220)은 실제 환경에서 시각을 맞출 길이 없어 가짜 샌드박스 시험으로만 확인했다.
- desk 터미널 경로의 실행(훅)은 이 실측에서 돌리지 않았다(시험과 F0 터미널 기준 사진으로만).
