# 실험 E9: 범위를 좁힌 계획은 작은 모델의 과잉 구현을 막는가

- 날짜: 2026-09-30 ~ 10-01 (KST 22:51 ~ 00:03)
- 관련 이슈: [#248](https://github.com/dj258255/b-studio/issues/248)(사전 등록), 변경 [#247](https://github.com/dj258255/b-studio/pull/247), 앞선 실험 [E8](2026-09-30-e8-plan-execute-split.md)
- 커밋: [e3449bc](https://github.com/dj258255/b-studio/commit/e3449bc)(#247 머지)를 고정한 작업 트리에서 돌렸습니다. 게이트 보강(#250)은 섞이지 않았습니다.
- 원자료: `~/.cache/b-studio/bench/coordination/e9-split-r{1,2,3}/`. 비교 기준은 E8의 결과를 그대로 씁니다. E8·E9 36행의 핵심 열은 [`data/2026-10-01-e9-results.csv`](data/2026-10-01-e9-results.csv)에 옮겼습니다.

## 왜 이 실험인가

E8에서 Opus 계획 + Haiku 실행(split)의 성공 1건당 비용은 $1.49로, Sonnet 단독의 6배였습니다. 성공은 5/9였습니다. 계획을 받은 Haiku는 Haiku 단독보다 파일 쓰기가 3배, 턴이 2배였습니다.

그래서 #247에서 계획 프롬프트를 이렇게 좁혔습니다.
- 요청이 요구하는 최소 변경만 적는다.
- 새 파일, 계층 분리, 테스트, 확인 단계는 요청할 때만 넣는다.
- 길이는 짧은 요청 150단어, 그 밖 400단어까지이고, 붙일 때 3,000자에서 자른다.
- 계획을 "참고 계획(요청 범위를 넘는 일은 하지 않는다)"으로 붙인다.

## 가설 (실행 전에 [#248](https://github.com/dj258255/b-studio/issues/248)에 적음)

- **H20**: E9-split의 성공 1건당 비용은 E8-split($1.49)의 절반 이하다.
- **H21**: E9-split의 평균 턴은 E8-haiku(31.6)의 1.3배(41) 이하다.
- **H22**: E9-split의 성공 1건당 비용은 E8-sonnet($0.23)보다 30% 이상 적다.

## 조건

| 조건 | 설정 |

| E9-split | S0, `--plan-model opus --execute-model haiku --plan-always`, 좁힌 계획 프롬프트, 과제 3개 × 3회 |
| 비교 기준 | E8-split, E8-haiku, E8-sonnet(같은 과제, 같은 벤치 설정. 다른 시각·커밋) |
| 공통 | 로컬 Claude Code 구독, 자가 확인 full, 단가는 E8과 같음(`opus` 별칭 → Opus 5) |

## 결과

9회 모두 유효했고 **9/9 성공**했습니다.

| 조건 | 성공 | 토큰 합 | 모델 호출 | 성공 1건당 토큰 | API 환산 비용 합 | 성공 1건당 비용 | 종단 중앙값 |
|---|---|---|---|---|---|---|---|
| E8-sonnet | 9/9 | 4,200,085 | 231 | 466,676 | $2.099 | $0.233 | 6.2분 |
| E8-haiku | 7/9 | 6,078,524 | 284 | 868,361 | $1.565 | $0.224 | 7.3분 |
| E8-split | 5/9 | 16,580,830 | 465 | 3,316,166 | $7.440 | $1.488 | 15.2분 |
| **E9-split** | **9/9** | 5,824,611 | 281 | 647,179 | $2.658 | **$0.295** | 8.2분 |

E9-split 비용 $2.66 중 계획 호출이 $1.14(43%)입니다. 계획 원문은 27건이고 평균 1,126자입니다. 승급은 한 번도 일어나지 않았습니다.

| 비교 | 검정 | p |
|---|---|---|
| 성공 E9-split 9/9 대 E8-split 5/9 | Fisher 정확(양측) | 0.082 |

짝지은 비교는 같은 과제·같은 회차끼리 묶었지만, 다른 날 다른 시각의 실행입니다.

## 결론

- **H20 확인**: 성공 1건당 비용이 $1.488에서 $0.295로 **80% 줄었습니다**(기준: 절반 이하). 9쌍 중 8쌍에서 쌌습니다(p = 0.027).
- **H21 확인**: 평균 턴 31.2로 Haiku 단독(31.6)과 같습니다(기준 41 이하). 파일 쓰기는 2.1로 네 조건 중 가장 적었습니다. **좁힌 계획은 과잉 구현을 막았습니다.**
- **H22 기각**: Sonnet 단독보다 성공 1건당 **27% 비쌌습니다**($0.295 대 $0.233). 계획 호출이 비용의 43%를 차지하기 때문입니다. 계획을 뺀 실행 비용만 보면 과제당 $0.169로 Sonnet($0.233)보다 쌉니다. 한두 문장짜리 과제에서는 큰 모델 계획 한 번의 고정비가 절약분을 넘습니다.
- **설명용 발견: 계획이 작은 모델의 실패를 막았습니다.** Haiku 단독이 3번 중 2번 실패한 order-summary(대시보드가 로딩에서 멈춤)를 E9-split은 3/3 성공했습니다. 전체 성공은 E9-split 9/9, Haiku 단독 7/9입니다(p = 0.47이라 확정은 아닙니다).

## 결정에 주는 영향

- ADR-075는 **기본 끔**을 유지합니다. 작은 과제에서는 Sonnet 단독이 가장 싸고, 성공도 같습니다.
- 좁힌 프롬프트는 그대로 둡니다. 계획을 켜는 경우에는 작업량과 비용을 크게 줄였습니다.
- 계획-실행 분리가 값을 할 곳은 **계획 고정비가 실행 절약분보다 작은 큰 과제**입니다. 실행이 길어질수록 계획 한 번의 비용 몫은 줄어듭니다. 이것이 다음에 잴 것입니다.

이 결론은 예제(Spring Boot api와 Next.js web), 작은 과제 3개, 조건별 9회에서만 확인했습니다.
