# 실측: 세션 터미널 실행의 닫기(화면 취소·터미널 닫기·검사 중 CLI 종료)를 실제 Claude Code로 보기 (B4a, ADR-210)

- 날짜: 2026-11-16
- 관련: 이슈 #1275(추적 #1274), 브랜치 `feat/b4a-terminal-close`, ADR-210, 트러블슈팅 230~232
- 모델: 이 컴퓨터에 로그인한 Claude Code(구독 로그인). 규칙표는 기본값 하나(claude-code)
- 환경: macOS arm64, 로컬 Docker(Colima). 지원 경로(이 컴퓨터 방식 세션 터미널)
  - 브랜치의 worktree에서 `pnpm studio launch --mode local --port 3923`으로 띄웠다. `B_STUDIO_EXPERIMENTAL`·`B_STUDIO_TERMINAL`을 지운 셸이고 health는 `"experimental":false`, `"terminal":true`였다.
  - 등록 목록·세션 폴더·로컬 토큰 파일(`B_STUDIO_LOCAL_TOKEN_FILE`)은 실측 전용 폴더를 썼다.
  - desk 화면 대신 세션 터미널 API로 몰았다. desk의 새 요청과 같은 순서다: `POST /api/sessions`(`terminal: true`, 첫 요청) → `POST …/terminal {action:'open'}`.
    - 터미널 출력(SSE)은 `@xterm/headless`(160x48)에 그려 글로 읽었다. 폴더 신뢰 창에는 실측 세션 폴더에만 "Yes, I trust this folder"를 골라 답했다.
    - 화면 취소는 `POST …/runs/:runId/cancel`, CLI 종료는 `POST …/terminal {action:'close'}`(PTY를 내림)로 했다.
    - 점유가 풀렸는지는 닫힌 뒤 터미널에 다음 요청("README.md의 첫 줄만 읽어서 알려 줘. 아무것도 고치지 마.")을 넣어 새 실행(`run_started`)이 열리는지로 봤다. 열리면 곧바로 취소했다.
  - 프로젝트: 화면 확인(`browser_check`)이 "shop 화면", "주문 합계"를 기대하는 정적 페이지 하나(`vf3`)
- 한 번씩 잰 값이다. 시각은 하네스가 세션을 만들기 시작한 때부터 잰 초다.

## 무엇을 보려 했나

B4a는 터미널 실행의 닫기 판정을 코어로 옮기고, 닫을 때 그 실행의 중단 신호를 끊고, 검사 중에 CLI가 끝났는데 검사가 재시도로 끝나는 칸을 실패로 닫게 했다. 가짜 훅 시험으로만 본 것을 실제 CLI와 실제 샌드박스에서 본다.

1. 화면 취소: 켜는 중인 세션, 준비된 세션에서 파일을 고친 뒤
2. 작업 중 터미널 닫기(CLI 종료, 피드백 없음)
3. 턴 끝 검사 도중 터미널 닫기 → 검사는 화면 확인 실패로 재시도(의심 2, 트러블슈팅 231). 고치기 전 코드(main 049c882)와 견줬다
4. 검사가 재시도 피드백을 돌려준 뒤 터미널 닫기

## 본 것

- 화면 취소와 터미널 닫기는 실제 세션에서도 그 자리에서(0.3~0.7초) 닫히고, 점유가 풀려 다음 요청이 새 실행으로 열린다.
- 닫기 판정의 세 칸을 실제로 지났다.
  - 켜는 중(`NoticeKept`): 켜기를 기다리던 첫 도구에서 취소나 닫기가 들어온 경우
  - 되돌림(`Revert`, 문서 보존 규칙 포함): 먼저 켠 세션
  - 검사 중 CLI 종료 → 재시도 → 실패(D2)
- 의심 2(트러블슈팅 231)는 실제 세션에서 닿는다. 고치기 전에는 받을 CLI가 없는데 실행이 열린 채 남았고, 다음 요청이 그 실행에 섞여 검사 재시도를 다 쓴 뒤에야 닫혔다. 고친 뒤에는 검사가 끝나는 자리에서 실패로 닫힌다.
- 하네스의 첫 시도에서 폴더 신뢰 창의 기본 선택("No, exit")에 Enter를 보내 CLI가 나갔다. 실행이 열리기 전이라 세션은 `idle`로 남았다. 하네스를 고쳐 Yes에 선택 표시가 붙은 것을 본 뒤 답하게 했다.

## 보지 못한 것

- **위반으로 닫히는 실행(결함 1, 트러블슈팅 230)**: 관문 파일 변조·훅 없는 CLI를 실제 세션에서 일으키지 않았다. 켜기를 기다리던 훅이 닫힌 뒤 거절하는 것은 가짜 샌드박스 시험으로만 확인했다. 실측의 취소·닫기 둘도 "켜기를 기다리던 첫 도구" 자리에서 닫혔지만, 화면 취소는 고치기 전에도 신호를 끊었고 닫기 뒤의 CLI는 이미 없었다. 그래서 고친 동작(닫기가 신호를 끊음)을 따로 보여 주지는 않는다.
- CLI 안에서 `/exit`를 친 경우. 터미널 닫기(PTY를 내림)로 CLI를 끝냈다. 진짜 Claude Code가 이때 SessionEnd 훅을 보냈는지, b-studio가 PTY 종료로 알았는지는 가르지 않았다.
- 닫는 도중 던지는 경우(트러블슈팅 232)와 D3 칸.
- desk 화면에 그려지는 끝 표시. API로 몰았다.

## 정리

- 실측 세션은 하네스가 끝에서 멈추고(`DELETE`) 지웠다(`POST …/delete`).
- 고치기 전 코드의 마지막 세션(`205e077b`)은 예외다. 하네스가 정리하는 중에 실측 studio를 먼저 멈춰서 두 요청이 502로 실패했다. 그래서 세션 기록과 작업 폴더가 실측 전용 폴더에 남았다. 그 세션의 컨테이너·네트워크·볼륨은 남지 않은 것을 `docker ps -a`·`network ls`·`volume ls`로 확인했다.
- 고치기 전 코드를 띄운 worktree는 지웠다. 다른 실측들처럼 세션 작업 폴더는 남았다.
