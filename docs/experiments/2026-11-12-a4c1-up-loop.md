# 실측: 컨테이너 만들기 반복과 override 쓰기를 Rust로 옮긴 뒤 실제 Docker로 켜 보기 (ADR-195 4f A4c-1)

- 날짜: 2026-11-12
- 관련: 이슈 #1180, 커밋 4a09b0d(브랜치 `feat/4f-a4c1-up-loop`, A4b #1178 위에 쌓임)
- 모델 호출: 없음. 세션을 만들고 "지금 켜기"(`POST /api/sessions/:id/boot`)와 서비스 끄기·켜기(`POST /api/sessions/:id/services/web/selection`)만 불렀다
- 환경: macOS, Colima의 Docker, `docker compose` v2. 이미지는 busybox:1.37 하나. 모두 한 번 잰 값이다

## 방법

- A4c-1 worktree에서 `pnpm build:native`·`pnpm build:server` 뒤 `pnpm studio launch --mode local --port 3923`. 등록 목록·세션 폴더는 실측 폴더 `~/.cache/b-studio/real4`([A4b 실측](2026-11-11-a4b-verify-containers.md)과 같은 프로젝트 `ok`·`bad`).
- `ok`: busybox httpd가 프로젝트 폴더를 `/work`로 마운트. `bad`: 같은 compose에 `privileged: true`.

## 결과

### 1. 정상 기동과 JSON override

- `ok` 세션은 boot 뒤 약 5초 만에 `ready`가 됐다.
- 컨테이너의 `com.docker.compose.project.config_files` 라벨이 가리키는 override 파일(`compose.override.yaml`, 30,273바이트)은 `{"networks":…`로 시작하는 JSON이다. compose가 이 파일로 컨테이너를 만들었다.
- 같은 내용을 옛 방식(`yaml` 패키지 `stringify`)으로 다시 쓴 YAML 파일을 만들어, 두 파일에 각각 `docker compose … config --format json`을 돌렸다. **결과가 바이트까지 같았다**(32,537바이트, edge 서비스의 34KB 넘는 `command` 스크립트 포함).
- 실제 override에는 `\u` 이스케이프가 없었다. 그래서 이스케이프하는 글자(U+2028, U+0085, BOM, 0x7F, 0x9F)와 따옴표·역슬래시·탭을 넣은 작은 JSON override를 따로 만들어 compose에 읽혔다. 모든 글자가 원래 코드 포인트 그대로 읽혔다.

### 2. 세션 중 compose에 마운트를 더한 뒤 다시 켜기

- 세션 작업 복사본의 `compose.yaml`에 `- ./:/work2`를 더하고, web을 끄고(`on:false`) 켰다(`on:true`).
- override 파일이 다시 쓰였다(수정 시각 00:54:59 → 00:56:25). web 마스크는 `/work/.git`, `/work/.git/b-studio`, `/work2/.git`, `/work2/.git/b-studio` 네 자리가 되었다.
- 다시 만들어진 web 컨테이너의 실제 마운트: `/work` rw=true, `/work2` rw=true, `/work/.git`·`/work/.git/b-studio`·`/work2/.git`·`/work2/.git/b-studio` 모두 rw=false.
- override 폴더에 `.tmp` 임시 파일은 남지 않았다.

### 3. 격리를 벗어나는 compose

- `bad` 세션은 `failed`가 됐다. 오류 글은 A4b와 같다(`… 시작하지 않았습니다 (studio-bad-5728c1)` / `web: privileged, security_opt: label=disable`). docker 이벤트는 edge `create`, web `create`, web `destroy`이고 web의 `start`는 없다.

## 보지 못한 것

- **만든 직후와 확인 사이에** compose가 바뀌는 경로(만든 뒤 다시 읽은 마스크가 달라 다음 시도로 넘어가는 경로, 세 번 안에 안정되지 않으면 내리는 경로)는 실제로 만들지 못했다. 시점을 맞출 방법이 없어 가짜 docker 차등 시험으로만 확인했다. 위 2는 "up과 up 사이"의 변경이다.
- override를 쓰지 못하는 경우(디스크·권한)는 실제로 만들지 않았다.
- 포트 충돌 재시도(`#regeneratePorts`)로 override를 다시 쓰는 경로는 돌리지 않았다(이 프로젝트에는 미리 정하는 포트가 없다).
- 서비스가 여럿인 프로젝트, Docker Desktop은 돌리지 않았다.

## 정리

- `ok` 세션은 `DELETE /api/sessions/:id`로 샌드박스를 멈춘 뒤 `POST …/delete`로 지웠고, `bad` 세션도 지웠다. 남은 컨테이너·네트워크가 없음을 확인한 뒤 `pnpm studio stop`.
