# 실측: 요청 분류를 코어로 옮긴 뒤 읽기만 요청 (2026-11-18)

[ADR-215](../decisions.md), 이슈 #1286. 요청 분류(읽기만·`/` 명령·읽기 도구)를 Rust 코어로 옮기고 읽기만 표시를 기다림 앞으로 당겼습니다(N1). 그 뒤 실제 세션에서 읽기만 요청이 여전히 쓰기를 막는지 봤습니다.

## 환경

- **기기와 CLI**: macOS arm64, 실제 Claude Code CLI 2.1.326(구독 로그인)
- **세션**
  - 이 컴퓨터 방식 세션 터미널, 실험 스위치가 꺼진 서버
  - 세션 모델 `haiku`. 구독 사용량을 아끼려고 골랐습니다.
- **코드**: 브랜치 `feat/b5a-terminal-classify`(c93efda). 서버는 실측 전용 폴더와 3923번 포트로 띄웠습니다.
- **하네스**: `measure-term.mjs readonly-pasted`. 세션 터미널 API로 몰았고 desk 화면은 보지 않았습니다.
  - 첫 요청은 평범한 `[읽기만]` 요청입니다. "README.md 끝에 한 줄을 Edit 도구로 더하려고 한 번 시도하고 거절 문구를 알려 달라"는 내용입니다.
  - 그 실행이 끝나면 같은 터미널에 bracketed paste(`ESC[200~ … ESC[201~`)로 여러 줄 `[읽기만]` 요청을 붙여 넣고 Enter를 보냅니다.
  - 붙여 넣은 줄 수를 달리해 두 번 돌렸습니다: 2줄, 그리고 참고 줄 20줄을 더한 22줄.

## 결과

| | 평범한 `[읽기만]` | 붙여 넣은 `[읽기만]` |
|---|---|---|
| 1회차(붙여넣기 2줄) | 실행 `6e76b513`: Edit 거절, `done`, 바뀐 파일 0개 | 실행 `28adddee`: Edit 거절, `done`, 바뀐 파일 0개 |
| 2회차(붙여넣기 22줄) | 실행 `a43a4b00`: Edit 거절, `done`, 바뀐 파일 0개 | 실행 `91e3f2fe`: Edit 거절, `done`, 바뀐 파일 0개 |

- 거절 문구는 네 번 모두 같았습니다: `PreToolUse:Edit hook error: [b-studio] 읽기만 요청이라 파일을 바꾸거나 명령을 돌리는 도구를 쓰지 않았습니다. …`
- 붙여 넣은 요청은 새 실행으로 열렸습니다. 서버가 받은 요청 글은 줄바꿈이 든 한 요청이었습니다.
- 모델은 다른 도구(Write·Bash)로 돌아가지 않았습니다. 그러라고 요청에 적었으므로 이것은 우회 시도를 막은 확인이 아닙니다.
- 정리: 세션 둘을 멈추고 지웠습니다. 세션 폴더, 컨테이너, 네트워크, 볼륨은 남지 않았습니다.

## 보지 못한 것

- **CLI 2.1.326이 붙여 넣은 요청을 `<pasted_content>`로 감싸는 모습은 보지 못했습니다.**
  - 22줄을 붙여 넣어도 화면에 `[Pasted text #N]`으로 접히지 않았습니다.
  - 1회차의 CLI 대화 기록에도 원문 그대로 남았습니다.
  - 감싸개는 2.1.302에서 봤던 꼴입니다(트러블슈팅 155). 감싼 입력과 이어 붙은 감싸개(N3)는 시험(세 구현 차등 68건 + 무작위 3000건)으로만 확인했습니다.
- **N1의 순서는 실제 세션에서 일으키지 못했습니다.** 요청 훅이 지문을 기다리는 사이에 쓰기 훅이 오는 순서입니다. 이 실측의 두 요청은 앞 실행이 닫힌 뒤 새 실행으로 열렸고, 열린 실행에 이어 붙지 않았습니다. 시험은 지문 읽기를 붙잡아 그 순서를 만듭니다.
- **확인 선언 변경 허용(N2)은 실제 세션에서 쓰지 않았습니다.**
- desk 화면은 보지 않았습니다.
