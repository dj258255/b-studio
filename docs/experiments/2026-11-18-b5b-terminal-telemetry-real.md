# 실측: 텔레메트리 입력을 코어로 옮긴 뒤의 턴 상한과 토큰 한도 세션 (2026-11-18)

[ADR-216](../decisions.md), 이슈 #1289.

B5b는 OTLP 본문 해석과 턴 상한 전이를 Rust 코어로 옮겼습니다. 그러면서 세 가지를 바꿨습니다.

- 모양이 틀린 `api_request`도 한 호출로 셉니다.
- 토큰을 읽지 못한 호출이 있으면 토큰 한도가 걸린 세션의 쓰기를 막습니다.
- 늦게 온 사용량이 새 실행의 끊김 판정을 끄지 못하게 했습니다.

이 실측에서는 두 가지를 봤습니다.

- 정상 세션이 "읽지 못함"으로 잘못 막히지 않는가
- 턴 상한이 그대로 걸리는가

## 실제 CLI 묶음 (본문 해석의 입력)

- **받은 방법**: CLI 2.1.326을 `claude -p --model haiku`로 한 번 돌렸습니다. b-studio와 같은 텔레메트리 환경 변수(`agentTelemetryEnv`)를 주고, 작은 수신 서버에서 묶음 넷을 받았습니다.
- **`api_request`**: 넷째 묶음에 한 건 있었습니다.
  - 정수는 `intValue`(JSON 숫자), 비용은 `doubleValue`로 왔습니다.
  - 이름은 속성 `event.name = api_request`에 있고, body는 `claude_code.api_request`입니다.
- **나머지 묶음**: 첫 묶음에는 훅·플러그인 기록 130여 건이 있었습니다. 둘째·셋째 묶음은 MCP 연결과 요청 기록입니다.
- **새 파서의 결과**
  - 네 묶음 모두 `defects=0`입니다. 읽지 못한 자리가 없으니 정상 묶음이 한도 세션을 막지 않습니다.
  - 넷째 묶음에서 호출 한 건을 꺼냈고, 토큰 값은 옛 파서와 같았습니다.
- **개인 정보**: 레코드에는 `user.email`, `organization.id`, 계정 id가 실려 옵니다.
  - 받은 원본은 지웠습니다.
  - 저장소에는 그 값들을 가짜로 바꾼 한 건만 넣었습니다(`apps/studio/lib/server/__fixtures__/claude-cli-2.1.326-api-request.json`).

## 환경

- **기기와 CLI**
  - macOS arm64
  - 실제 Claude Code CLI 2.1.326, 구독 로그인
- **세션**
  - 이 컴퓨터 방식 세션 터미널, 실험 스위치가 꺼진 서버
  - 세션 모델 `haiku`
- **코드**: 브랜치 `feat/b5b-terminal-telemetry`(7fd6d90)
- **서버**
  - 실측 전용 폴더와 3923번 포트를 썼습니다.
  - **사람별 토큰 한도 `B_STUDIO_USER_TOKEN_LIMIT=500000000`을 걸었습니다.** 한도에 닿지 않을 만큼 큰 값이지만, 한도가 걸린 세션이 되어 "읽지 못함" 판정을 거칩니다.
- **하네스**: `measure-term.mjs pass`(프로젝트 vf3), `measure-term.mjs max-turns`(프로젝트 mt, `workflow.maxTurns: 2`)

## 결과

### 토큰 한도가 걸린 정상 세션 (`pass`)

| 시각 | 본 것 |
|---|---|
| 14.5초 | 실행 `70418f3c` 열림 |
| 19.1~35.5초 | 사용량 다섯 건이 이 실행에 붙음 |
| 25.2초 | Edit 허용 |
| 49.0초 | 게이트를 지나 `done`, 체크포인트 |
| 53.2초 | 다음 요청이 새 실행 `6ad37570`으로 열림(취소함) |

읽지 못함으로 막힌 쓰기는 없었습니다.

### 턴 상한 (`max-turns`, 상한 2)

| 시각 | 본 것 |
|---|---|
| 14.2초 | 실행 `c10e5f39` 열림 |
| 19.1초 | 사용량 두 건이 실행에 붙음(모델 호출 2) |
| 약 25초 | 첫 Edit가 쓰기 직전 훅에서 거절됨: "턴 상한(2)에 닿았습니다. 지금까지 한 것을 정리하고 턴을 끝내세요" |
| 27.9초 | CLI가 우회하지 않고 턴을 끝냄. `done`, 바뀐 파일 0개 |
| 32.1초 | 다음 요청이 새 실행 `bfff7187`로 열림(취소함) |

- 거절 글은 토큰 한도가 걸린 서버에서도 "턴 상한"이었습니다. 읽지 못함 글이 아닙니다.
- B4d 실측(같은 프로젝트, 옮기기 전 코드)과 같은 결과입니다.

### 정리

세션 둘을 멈추고 지웠습니다. 세션 폴더, 컨테이너, 네트워크, 볼륨은 남지 않았습니다.

## 보지 못한 것

- **실제 CLI가 모양이 틀린 `api_request`를 보내는 모습은 보지 못했습니다.** 받은 묶음은 모두 정상이었습니다. 모양이 틀린 레코드와 깨진 본문은 시험(무작위 3000건)으로만 확인했습니다.
- **늦게 온 사용량이 새 실행에 붙지 않는 칸(N5)은 실제 세션에서 일으키지 않았습니다.** 앞 실행이 닫힌 뒤 1초 안에 새 실행이 열려야 하는 순서입니다.
- **시각이 60초 넘게 어긋난 레코드**는 시험으로만 확인했습니다.
- **desk 화면**은 보지 않았습니다.
