# B4c 실측: 세션 터미널의 턴 끝 판정을 코어로 옮긴 뒤 (2026-11-17)

[ADR-212](../decisions.md), 이슈 #1280. 이 변경으로 바뀐 것은 세 가지입니다.

- 턴 끝(Stop 훅) 판정을 Rust 코어의 순수 판정으로 옮겼습니다.
- 실행 도중 `[읽기만]`이 이어 와도 앞선 변경이 게이트를 지나게 했습니다(S6).
- 저장 중 위반, 커밋 뒤 실패, 재시도 셈의 틈을 닫았습니다.

여기서는 두 가지를 봅니다. 하나는 지원 경로의 턴 끝 네 갈래(통과·재시도·소진·읽기만)가 실제 CLI에서 그대로 도는지입니다. 다른 하나는 S6을 실제 세션에서 일으켜 고치기 전과 비교하는 것입니다.

## 환경

- macOS arm64, Node 22.17, 로컬 Docker(Colima)
- 실제 Claude Code CLI(구독 로그인), 이 컴퓨터 방식 세션 터미널(기본값), 실험 스위치가 꺼진 서버
- 고친 코드: 브랜치 `feat/b4c-terminal-turn-end`(1f51553)
- 고치기 전 코드: main ab3fc78을 임시 worktree에서 같은 방식으로 띄웠습니다.
- 서버는 실측 전용 폴더(`~/.cache/b-studio/real4`)와 3923번 포트로 띄웠고, 네이티브 모듈은 마지막 Rust 변경 뒤에 빌드했습니다.
- 프로젝트: `vf3`(정적 `index.html` + `order.json`, HTTP·브라우저 화면 확인)
- 하네스 `measure-term.mjs`(B4a에서 만듦): 이번에 `exhaust`·`readonly-after-work` 시나리오를 더했습니다.
  - `readonly-after-work`: 첫 Edit로 파일이 바뀌면 CLI에 Esc를 보내 턴을 끊습니다. 실행은 열린 채 남습니다. 그다음 같은 실행에 `[읽기만] 방금 무엇을 바꿨는지 한 문장으로만 알려 줘` 요청을 보냅니다.

## 결과 (고친 코드)

| 시나리오 | 결과 |
|---|---|
| 작업 뒤 읽기만(`readonly-after-work`, S6) | 24.5초 Edit, 30.7초 파일이 바뀜, 32.2초 Esc. 끊은 뒤에도 실행은 열려 있었습니다(`running: true`). 35.8초 `[읽기만]` 요청이 같은 실행 `44224bf0`에 붙음(`terminal_prompt`). 턴 끝에서 40.5초에 검사가 시작됐고 55.4초 `gate_done`, 56.1초 `done`. 앞선 Edit는 체크포인트로 남았습니다(ahead 1, 남은 변경 0). |
| 소진(`exhaust`) | 화면 확인이 실패하는 Edit를 고치지 않고 둠. 게이트가 세 번 돌아(46.0초·53.4초·60.2초 `verify_result`) 앞의 둘은 재시도였고, 셋째에서 `failed`. "검증 게이트를 3번 통과하지 못했습니다 / 바뀐 파일 1개를 되돌렸습니다". 남은 변경 0. |

| 읽기만(`readonly`) | `[읽기만]` 요청의 Edit가 훅에서 거절됨. 30.6초 `done`, 바뀐 파일 0개, 체크포인트 그대로. |

모든 경우에 다음 요청이 새 실행으로 열렸습니다. 하네스는 세션마다 멈추기·지우기(200, 200)로 정리했고, 정리가 끝난 뒤 studio를 껐습니다. 컨테이너·네트워크·볼륨·세션 폴더가 남지 않은 것도 확인했습니다.

## 고치기 전 코드(ab3fc78)와 비교: 작업 뒤 읽기만

같은 시나리오를 고치기 전 코드로 한 번 돌렸습니다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| `[읽기만]`이 같은 실행에 붙음 | 35.0초(`89f662cb`) | 35.8초(`44224bf0`) |
| 턴 끝의 게이트 | **돌지 않음**(`verify_start` 없음). 3초 뒤 38.3초에 `done` | 돎. 55.4초 `gate_done` 뒤 `done` |
| 앞선 Edit(`README.md`) | **체크포인트 없이 작업 복사본에 남음**(`/changes`에 `README.md` modified) | 체크포인트로 남음(남은 변경 0) |
| 다음 요청을 취소하면 | 그 변경이 "문서 1개(README.md)는 되돌리지 않고 체크포인트로 남겼습니다"로 **검증 없는 문서 체크포인트**가 됨 | 남은 변경이 없어 그대로 |

고치기 전에는 사람이 읽기만을 붙이는 순간, 앞서 에이전트가 바꾼 파일이 게이트를 지나지 않은 채 `done`으로 묻혔습니다. 이번에 바꾼 파일은 `README.md`라 문서 체크포인트 규칙(ADR-096)에 따라 다음 실행에서 검증 없이 남았습니다. 코드 파일이었다면 체크포인트 없이 작업 복사본에 남았을 것입니다(코드 파일로는 재지 않았습니다).

## 보지 못한 것

- **S1·S14·S12를 실제 세션에서 일으키지 않았습니다.**
  - S1(저장 중 위반)과 S14(커밋 뒤 실패)는 저장하는 짧은 사이에 위반이나 오류를 맞춰 넣어야 합니다. 실제 세션에서는 그 때를 맞출 수 없어 시험으로만 확인했습니다.
  - S12(재시도 셈 합산)는 게이트 밖 사유(검증 중 파일이 바뀜)를 실제로 일으켜야 해서 재지 않았습니다. 위 소진 시나리오는 게이트 실패만 세 번이라 옛 셈과 결과가 같습니다.
- **읽기만이 켜진 뒤 훅을 우회한 변경, 훅을 거치지 않은 앞선 변경:** 시험으로만 확인했습니다.
- **Stop 훅 상한(3600초):** 재지 않았습니다.
- **desk 화면:** 보지 않았습니다. 세션 터미널 API로 desk와 같은 순서를 밟았습니다.
- **반복:** 고치기 전 비교는 한 번만 돌렸습니다.
