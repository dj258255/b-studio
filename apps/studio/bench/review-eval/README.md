# 리뷰 평가 세트

AI 리뷰(PR 리뷰)를 결함을 심은 diff 세트로 재는 벤치입니다. 리뷰 프롬프트나 모델을 바꿀 때 **바꾸기 전과 후를 같은 세트로** 견주려고 만들었습니다.

현재 상태: 채점기와 세트는 가짜 응답으로만 시험했습니다. **아직 실제 모델로 잰 결과가 없습니다.** 이 문서에 재현율 같은 숫자를 적지 않은 이유입니다.

## 세트

`cases.ts`에 직접 쓴 작은 코드 조각 18개가 있습니다(저장소나 모델 호출에 기대지 않습니다).

- 결함 있는 항목 14개: TypeScript 7개, Python 7개. 결함 종류 8가지(off-by-one, null 처리 누락, SQL 주입, 명령 주입, 오류 삼킴, 경계 조건, 동시성 경합, 권한 확인 누락)
- 결함 없는 항목 4개(오탐 측정용): 같은 주제의 올바른 코드
- 항목마다 기대 지적(파일, 새 파일 기준 줄 범위, 종류 태그)을 적습니다. 줄 번호는 손으로 세지 않고 결함이 든 줄의 글자로 찾습니다(`lineNumberOf`)
- 세트를 고치면 `EVAL_SET_VERSION`을 올립니다. 결과 파일에는 세트 내용의 해시가 남아, 세트가 다른 결과끼리는 비교되지 않습니다

## 채점(결정론, 모델을 쓰지 않음)

리뷰어에게 보내는 프롬프트는 제품이 쓰는 `buildPrReviewSystemPrompt`·`buildPrReviewUserPrompt`로 만들고, 응답은 제품과 같은 `parsePrReviewReply`로 읽습니다.

- **맞음**: 지적의 파일이 기대 지적의 파일과 같고(`a/`·`b/` 접두, `./`, 역슬래시, 겹친 `/`만 같게 봅니다) 지적의 줄이 기대 줄 범위 안(양 끝 포함)입니다. 줄이 없는 지적은 맞음이 아닙니다. 심각도와 제목은 보지 않습니다
- 기대 지적 하나를 여러 지적이 가리켜도 한 번만 맞습니다
- **범위 밖 지적**: 결함 있는 항목에서 어떤 기대 지적에도 맞지 않은 지적 수
- **오탐**: 결함 없는 항목에서 나온 지적 수(전부 오탐)
- **응답 못 읽음**: 파싱 실패, 스키마 불일치, 호출 실패. 기대 지적을 놓친 것으로 세고(재현율 분모에 남음) 결함 없는 항목도 "통과"로 세지 않습니다
- 참고로 지적의 위치가 리뷰한 diff에 없는 수(`notInDiff`)도 셉니다(#1440의 위치 대조를 그대로 씁니다)
- 합계: 전체·종류별·언어별 재현율(맞은 기대 지적 / 전체 기대 지적), 오탐, 범위 밖, 못 읽음

## 실행

```sh
# 본인 PC에 로그인된 Claude Code 구독 CLI로 항목마다 한 번씩 묻는다(도구 없음)
pnpm bench:review-eval --ask claude-code --model sonnet --out before.json

# 기대 지적을 그대로 돌려주는 가짜 리뷰어. 배선 확인용이라 모델 성능이 아니다
pnpm bench:review-eval --ask fake

# 프롬프트나 모델을 바꾼 뒤 같은 명령으로 다시 재서 견준다
pnpm bench:review-eval:compare before.json after.json
```

결과 JSON에는 세트 해시, 프롬프트 해시(시스템 프롬프트와 모든 항목의 사용자 프롬프트), 모델, 항목별 결과(모델 원문 포함), 합계가 들어 있습니다. 세트 해시가 다르면 비교 명령은 비교하지 않고 종료 코드 1로 끝납니다.

## 읽는 법과 한계

- 항목 하나가 한 번 묻는 한 번의 응답입니다. 같은 설정에서도 응답이 흔들리므로, 작은 차이는 반복해 재기 전에는 개선이나 퇴보로 읽지 않습니다
- 항목이 18개(기대 지적 14개)라 맞음 하나가 재현율을 7%포인트 남짓 움직입니다
- 한 번 호출은 diff와 요청 한 줄만 줍니다. 제품의 라운드 문맥(바깥 참고 파일, 사람이 닫은 지적)은 넣지 않았습니다
- 줄 범위는 결함이 든 줄과 그 바로 이어지는 줄까지로 좁게 잡았습니다. 리뷰어가 결함의 원인을 다른 줄(예: 함수 머리)로 가리키면 놓침으로 셉니다
- 시험(`*.test.ts`)은 가짜 응답만 씁니다. 실제 모델 호출은 시험에서 하지 않습니다
