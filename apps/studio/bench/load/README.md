# 스튜디오 부하 스모크 (`pnpm bench:studio-load`)

스튜디오 자체의 세션 기동과 SSE 이벤트 전달이 부하에서 어떻게 버티는지 재는 스모크입니다. 판정하지 않고 값만 남깁니다.

- **Docker를 띄우지 않습니다.** 가짜 샌드박스 제공자(`sandbox-shim.ts` → `fake-provider.ts`)가 서비스를 곧바로 ready로 만들고, 초당 `--rate`개의 가짜 로그 이벤트를 흘려보냅니다.
- **모델을 부르지 않습니다.** 요청을 보내지 않고 세션을 만들고 이벤트만 흘리므로 모델 레지스트리도 필요 없습니다.
- 세션마다 **실제 SSE 라우트**(`app/api/sessions/[id]/events/route.ts`)로 연결을 열어 두고, 흘려보낸 이벤트가 구독자에게 도착하는 지연을 잽니다.

## 실행

```bash
# 기본: 세션 5개, 세션당 초당 50개, 5초
pnpm bench:studio-load

# 조절
pnpm bench:studio-load --sessions 8 --rate 100 --duration 10

# JSON으로도 남기기
pnpm bench:studio-load --out ./studio-load.json
```

인자:

- `--sessions N` — 동시에 띄울 세션 수(기본 5). 세션은 하나씩 만들어 생성 지연을 잰 뒤, 모두 만든 다음 이벤트를 함께 흘립니다.
- `--rate N` — 세션당 초당 이벤트 수(기본 50). 전체 부하는 `세션 수 × rate`입니다.
- `--duration S` — 준비가 끝난 뒤 이벤트를 흘려보내는 시간(기본 5초).
- `--out <파일>` — 결과 JSON을 쓸 경로(없으면 표만 출력).

## 재는 것

- **세션 생성 지연** — `createSession`이 돌아오기까지(샌드박스 기동 전, 작업 복사본 준비까지). p50·p95·최대·평균
- **SSE 첫 이벤트까지 지연** — 연결을 연 시각부터 첫 `data:` 프레임까지
- **이벤트 전달 지연** — 가짜 이벤트를 만든 시각(로그 줄의 `at`)부터 SSE 구독자가 받은 시각까지. p50·p95·최대·평균
- **프로세스 RSS** — 시작 시점과 실행 중 최고
- **보낸 이벤트 / 받은 이벤트 / 떨어진 이벤트 수**

## 한계

- **가짜 제공자입니다.** 컨테이너 기동, 이미지 빌드, Gradle·pnpm 의존성 설치 시간은 재지 않습니다. 여기서 재는 것은 스튜디오 서버 안쪽(세션 관리·이벤트 버스·SSE 직렬화)의 지연입니다.
- **Next HTTP 전송 계층은 지나지 않습니다.** 실제 라우트 핸들러를 프로세스 안에서 직접 불러 스트림을 읽습니다. 네트워크·프록시 홉의 지연은 빠집니다.
- **한 프로세스 안입니다.** 세션 N개는 같은 스튜디오 프로세스에서 돕니다. 여러 프로세스가 한 저장소를 공유하는 경우는 재지 않습니다.
- 이 PC·이 커밋에서의 값입니다. 기준선은 메인 세션이 실행해 문서(`docs/verification.md`)에 남깁니다.
